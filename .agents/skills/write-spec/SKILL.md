# write-spec

## 절차

1. docs/product-plan.md에서 요청이 MVP 범위 안인지 확인함. 범위 밖이면 멈추고 사용자에게 알림
2. 근거가 되는 product-plan 장이나 사용자 요청을 "관련 기획"에 적음 (기획서 원본은 레포 밖에 있으므로 장 번호만 인용 가능)
3. docs/specs/_template.md를 복사해 `docs/specs/<kebab-case-기능명>.md`로 만듦
4. 각 장을 채움:
   - **범위**: 포함과 제외를 모두 씀. 제외를 비워 두지 않음
   - **API**: 메서드, 경로, 인증, 성공·실패 상태 코드
   - **데이터**: 새 테이블·필드와 제약
   - **완료 조건**: 체크박스로, 테스트로 확인 가능한 문장 (예: "기업이 없으면 404를 반환함")
   - **미정 사항**: product-plan이나 사용자 확인에 근거가 없는 결정은 여기에 적고 추측해 채우지 않음
5. 상태를 `초안`으로 두고 사용자에게 확정을 요청함
6. update-todo 스킬로 todolist에 작업을 추가하고 spec 이름을 연결함

## 좋은 완료 조건 / 나쁜 완료 조건

| 나쁨 | 좋음 |
| --- | --- |
| 로그인이 잘 됨 | 같은 제공자 계정으로 다시 로그인하면 새 사용자를 만들지 않음 |
| 에러 처리함 | 허용되지 않은 발생 주기 값은 422를 반환함 |
