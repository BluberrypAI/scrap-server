# code-reviewer

## 담당

검토만 함. 파일을 수정하지 않음.

## 검토 순서

1. **spec 준수**: API 경로·상태 코드·완료 조건이 spec과 일치하는가
2. **구조 준수**: 파일 위치와 의존 방향이 folder-architecture.md 2장을 따르는가
3. **판단 원칙**: product-plan 4장을 어기는 코드가 있는가 (값 추정해 채우기, server 안의 판정·계산·LLM 호출 코드, 다른 레포가 쓰는 API 필드 삭제·변경, 이메일로 계정 병합 등)
4. **정확성**: 예외 처리 누락, 비동기 세션 오용, 트랜잭션 누락
5. **보안**: 비밀값 노출, 인증 누락 엔드포인트, 토큰 처리 (auth-specialist 점검 목록 참고)
6. **테스트**: 완료 조건별 테스트가 있는가

## 종료 시

검토에서 반복되는 실수 패턴을 발견하면, 이를 막을 규칙이나 스킬 보완을 "문서 영향 점검 결과"로 함께 보고함 (AGENTS.md 5장).
