# 업체가 직접 반입조건을 정하고 답변하는 흐름

## 달라진 점

업체가 가입하고 자기 처리 사업장과 연결되면, 웹의 **기업 데이터 관리 → 반입조건**에서
받는 재질·형태, 오염·수분, 포장, 반입 일정, 최소·최대 kg, 수락 전 확인할 자료를 등록합니다.
모르는 물량 범위는 비워 둡니다. 업체가 쓴 안내이며 현재 허가·처리능력을 인증한 자료가 아닙니다.

배출기업은 기존 문진과 현재 물량 검토로 후보를 찾습니다. 후보에서 업체 등록 조건을 보고
인수 요청을 보내면 두 기업 사이의 문의가 열립니다. 양쪽은 문의 화면에서 답변을 남길 수 있습니다.
필수 확인 조건이 있으면 업체가 **조건부 수락**을 제시하고, 배출기업이 조건별 자료를 입력한 뒤
수신기업이 이를 확인해야 최종 수락됩니다. 그때부터 발송기업의 QR 발급과 수신기업의 입고가 가능합니다.
답변 자체는 승인이나 운송 시작이 아닙니다.

등록한 물량 범위 등 자유서술 조건은 이번 버전에서 업체 확인용으로 표시합니다.
AI가 새 등록 조건의 적법성이나 내용을 인증하지 않습니다. 공정·공개 근거·물량 AI 검토와 구분합니다.

## 데이터와 권한

- 새 PostgreSQL 테이블 `supplier_intake_policies`: 사업장·등록기업·버전·조건·등록시각. 수정은 기존 행 덮어쓰기 대신 새 버전으로 저장합니다.
- 기존 `workflow_offers.data.facility.supplier_policy`: 문의 당시 조건. 이후 업체가 조건을 바꿔도 이미 보낸 문의 조건은 유지합니다.
- 기존 `workflow_offers.data.messages`: 발신기업·내용·시각. 인계별 최대 100개, 한 답변 최대 1,000자.
- 이력은 입고 후에도 물량·확인 사항에서 읽을 수 있습니다. 현재 인계의 발송자·수신자만 답변할 수 있습니다. B→C에서 이전 배출자 A는 이력을 읽지만 대신 답변할 수 없습니다.
- 등록 조건 변경 후 이전 후보 검토로 요청하면 다시 검토를 요구합니다. 접수 중단 업체에는 새 요청이 차단됩니다.
- 공개 명부의 업체 이름만으로 다른 업체의 조건을 등록할 수 없습니다. 운영용 사업장-기업 연결 확인 절차는 별도입니다.
- 외부 이메일·문자 발송은 없고, 실제 업체 연락도 하지 않았습니다.

## 적용 순서

1. server #52 최신 코드 적용 후 `uv run alembic upgrade head`. 새 리비전은 `a87485f30805`.
2. web #53 최신 코드 적용. 새 환경변수와 route/diagnosis 변경은 없습니다.
3. 확인된 시설-기업 연결을 사용합니다. 로컬 시험의 synthetic 연결은 운영에서 사용할 수 없습니다.
4. 업체 조건을 등록한 뒤 진행 중인 물량에서 **다시 검토**를 실행합니다.

## 자동 검증

- 서버 전체 **529개**, 웹 **67개** 통과. Ruff 검사·포맷 검사와 웹 프로덕션 빌드 통과.
- 타사 조건 수정, 오래된 버전 수정, 조건 변경 후 오래된 검토 요청, 신규 문의 중단 차단.
- 문의 시점 조건 보존, 조건 자료 없이 최종 수락 불가, 수락 전 QR 불가, 수신기업만 입고 가능.
- 별도 A/B/C/D 계정 API로 당사자 답변·제3자 차단·과거 A의 B→C 답변 차단 검증.
- 임시 SQLite에서 새 migration upgrade → downgrade → upgrade와 alembic check 통과. 실제 로컬 PostgreSQL에도 신규 migration 적용.

## 실제 웹 검증

2026-11-17, localhost:5178에서 별도 개발용 A/B 기업 계정으로 직접 클릭해 확인했습니다.
시험용 물량 1,000kg, 조건·검사 수치·수락은 합성 데이터이며 실제 업체 반입 승인이 아닙니다.

1. B: 기업 데이터 관리 → 반입조건에서 연결된 시험 사업장에 PP 잔재·오염·마대 포장·일정·100~2,000kg·필수 수분 자료 조건 저장. 1차 저장 완료 확인.
2. A: 실제 문진을 새로 진행해 PP/51-03-01을 확정하고 사출 잔재 형태와 물량을 등록.
3. A: 실제 Azure 후보 검토 후 새롬이엔지 화성 제2공장 시험 연결의 등록 조건을 확인하고 인수 요청.
4. A가 포장·자료·일정을 문의하고, B로 다시 로그인해 문의를 읽고 답변. 두 기업명과 작성시각이 서버에 저장됨.
5. B가 등록된 필수 조건으로 조건부 수락. A의 자료 제출 전 최종 수락 버튼 비활성, A의 QR 버튼 없음 확인.
6. A가 조건별 합성 자료를 제출. B로 다시 로그인해 자료 확인 체크 전에는 최종 수락 불가, 체크 후 최종 수락 성공.
7. A가 입고 QR을 발급하고 링크를 복사. B로 로그인해 같은 링크를 열고 입고 확인 성공. 휴대폰 카메라 스캔 시험은 아님.
8. 입고 후 B가 현재 담당으로 바뀌고, A로 재로그인해 입고 확인 체크·처리 중 상태·8건 이력을 확인. 물량·확인 사항에는 문의 당시 1차 조건과 양쪽 대화가 보존됨.

이 시험의 후보 14개 중 Azure 검토 완료 12개, 미완료 2개였습니다. 선택한 B 후보는 검토 완료 상태이며
미완료 2개(중일머티리얼즈 인천·대운프라스틱 나주)를 승인한 것이 아닙니다.
사진 없이 등록 조건·문의·조건부 수락 연결에 집중한 시험입니다. 사진 검증, 다른 소재, B→C 전체 웹 재시험을 했다는 뜻은 아닙니다.
B→C 대화 권한은 자동 회귀에서 확인했습니다. 기존 PP 직접/두 단계 전체 웹 검증은 별도 보고서에 기록돼 있습니다.

문의 답변은 인계 당사자 화면에만 남겼으며 실제 업체에 연락하지 않았습니다.

## 남은 운영 준비

실제 업체 계정과 사업장 소유·권한 확인, 최신 허가 확인, 실제 검사·반입조건 자료 확보가 필요합니다.
자기신고 조건·로컬 시험 계정·합성 증빙을 실제 반입 승인으로 해석하지 않습니다.
이번 변경은 서비스 안에서의 문의·승인·입고 기록 연결입니다.
