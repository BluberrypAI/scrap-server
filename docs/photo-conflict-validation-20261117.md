# 사진과 설명이 다를 때 인수 요청을 막는 흐름

## 바뀐 점

1. 어느 후보의 AI 검토에서든 사진·설명의 명확한 모순이 나오면 모든 업체에 인수 요청을 보류합니다.
2. 사용자는 설명을 고쳐 재검토하거나, 기존 문진 내용이 같다는 체크와 확인 사유를 남깁니다.
3. 설명을 고치면 기존 검토가 초기화됩니다. 확인만 남기면 AI의 원래 우려와 확인 사유를 수신 업체에 같이 전달합니다.
4. 최종 수락은 여전히 수신 업체가 합니다. 분류번호·R유형·문진 원본을 사진 때문에 바꾸지 않습니다.
5. 재질·발생 공정·유해성 답변이 달라졌거나 불확실하면 재문진을 안내합니다. 새 문진은 별도 건이며 기존 건에 자동 덮어쓰지 않습니다.

## 자동 검증

- 서버 전체 539개 통과, Ruff 검사 통과. 새 회귀 8개 포함.
- 웹 전체 69개 통과, 프로덕션 Docker 빌드 통과. 기존 큰 번들 경고는 남아 있습니다.
- 다른 업체 선택으로 차단 우회 불가, 다른 기업 수정 불가, 오래된 버전 거절, 확인 사유/체크 누락 거절.
- 설명 수정 뒤 재검토 필수, 분류번호·R유형 보존, 수신자에게 원래 우려와 확인 사유 전달.
- 새 사진·새 검토·산출 단계·현재 보유 기업이 바뀌면 이전 확인 무효화.
- 자동 회귀의 AI 응답은 합성 자료입니다. 아래 웹 시험은 실제 Azure를 호출했습니다.

## 실제 웹 시험

- localhost:5178 → server:8000 → route:8010, 로컬 A 시험 기업.
- 처리 건: 858d3bef-aac2-4985-b535-c292e1b1cf94. PP 파쇄품 950kg 합성 물량. 실제 업체에 연락하거나 실제 운송하지 않았습니다.
- 사진: 기존 프로젝트의 WUR 연구자료 PP 조각 사진(doi:10.18174/518299, Figure 6.1). 흰색과 여러 색 조각이 보입니다. 사진 파일은 저장소에 추가하지 않습니다.
- 잘못된 설명: “흰색 조각만 있고 빨강·파랑·노랑 조각은 전혀 없습니다.”
- Azure가 9개 공정·업체 조합을 검토하고 색 조각과 설명의 모순을 반환했습니다. UI에서 모든 인수 요청이 차단됐습니다.
- 사유만 입력한 상태에서는 확인 버튼이 비활성. 기존 문진과 같다는 체크 후 확인 기록이 저장되고 요청 버튼이 표시됐습니다. 이 확인 경로는 합성 기능시험으로만 실행했고 요청을 발송하지 않았습니다.
- 이후 설명을 “여러 색 조각이 함께 보이며 순도·수분·유해성은 미확인”으로 수정했습니다. 분류번호 51-03-01은 그대로이고 기존 검토/요청 버튼이 사라졌습니다.
- 수정 후 실제 Azure 재검토: 9/9 완료, 사진·설명 불일치 0건. 독산 화성에 연결된 로컬 C 가상기업에 웹에서 인수 요청을 보냈고 응답 대기 상태를 확인했습니다. 수정된 설명과 사진이 요청에 담겼고 분류번호 51-03-01은 유지됐습니다.
- 스크린샷은 로컬 output/verification/photo-conflict-20261117/blocked.jpg와 requested.jpg. 시험 화면: http://localhost:5178/#/wastes/case-36a09fc25406427b96b91a79262095a6
- 이번 웹 시험은 요청 생성까지이며, 새 요청의 수신 기업 수락·QR·완료를 반복 실행한 시험은 아닙니다. 기존 QR/완료 회귀는 서버 전체 검사에 포함됩니다.

## 적용 범위와 남은 점

- server와 web을 함께 적용해야 합니다. 새 DB 마이그레이션/키는 없습니다. route 엔진은 기존 사진 관찰·후보 검토를 그대로 사용합니다.
- 이번 검증은 상태 전이와 요청 차단에 대한 것입니다. 사진 AI의 모든 오염·재질 판별 정확도를 보장하지 않습니다. 사진으로 순도·유해성·법적 분류를 확정하지 않습니다.
- 문진 자체의 답변이 바뀐 경우 기존 인계 건과 새 문진 결과를 대체 연결하는 업무 절차는 별도입니다.
- AGENTS.md/.agents 운영 규칙 변경은 없습니다.
