# Spec: 현재 상태에서 가능한 다음 공정 누락 방지

| 항목 | 내용 |

| 상태 | 구현·로컬 검증 완료 — 2026-11-15 |
| 관련 기획 | 사용자 요청: 가능한 경로 최대한 연결. A는 B를, B는 실제 산출물로 C를 선택 |
| 관련 todo | T-150 |

## 1. 목적

최종 산출물까지 자료가 이어져야 첫 공정을 표시하던 의존성을 없앤다. 업체가 없어도 근거가 있는 다음 공정과 확인 조건은 남긴다.

## 2. 범위

- 포함: 현재 상태의 모든 등록 전이, 완료 이력 연속성 검사, 제한된 후속 공정 미리보기, 공정만 있는 결과의 웹 표시, 근거 기반 참조 자료 확장.
- 제외: 미확인 업체의 처리능력 생성, 분류번호 자동 변경, 업체 없는 공정의 인수 요청, A가 C를 확정하는 전체 공급망 예약.

## 3. 요구사항

1. 현재 상태에서 직접 이어지는 전이는 후속 최종 상태·업체 유무와 관계없이 조회된다.
2. 후속 탐색 예산이 소진돼도 지금 선택 가능한 전이는 빠지지 않는다. 미리보기 일부 생략은 응답에 명시한다.
3. 연결된 업체가 없거나 중간 공정이 막혀도 처리 완료로 바꾸지 않는다. 완료 가능한 산출 상태는 기존 명시적 기준을 따른다.
4. 완료 공정 이력은 연결 순서·재질을 검사한다. 실제 산출물이 있으면 해당 상태에서 다음 공정을 찾는다.
5. 위치 Top 5는 업체 표시만 제한한다. 업체 없는 공정도 근거·확인 조건과 함께 보인다.
6. 신규 업체·공정은 공개 출처 범위로만 연결한다. 반입 승인·허가·현재 용량은 미확인으로 둔다.

## 4. API

기존 POST `/api/treatment/next-step` 및 문진·기업 인계 중계 계약 유지.
응답에 `process_previews_truncated: boolean`을 추가한다. 200 결과의 상태 값은 유지하며, 잘못된 완료 이력은 기존 오류로 반환한다.

기존 `/api/treatment/facility-web-search`의 지원 공정을 전체 활성 소재로 확장한다. 서버가 등록 공정의 `material`, `process_label`, `operation_steps`를 AI에 전달한다. 사용자의 기업 정보·사진·좌표는 이 검색 요청에 넣지 않는다. 웹 결과는 별도 조사 단서이며 자동 업체 연결·허가·인수 승인으로 쓰지 않는다.

## 5. 데이터

새 테이블 없음. PostgreSQL 참조 전이·업체 자료와 현재 입력·실제 산출물만 사용한다. 기존 전체 경로 탐색 함수의 의미는 바꾸지 않는다.

## 6. 완료 조건

- [x] 등록된 모든 직접 전이를 현재 입력/산출 상태에서 찾는다.
- [x] 최종 상태로 이어지지 않는 중간 공정도 표시하고, 종료는 허용하지 않는다.
- [x] 후속 경로가 탐색 한도를 넘겨도 직접 후보는 유지한다.
- [x] 순서가 맞지 않는 완료 이력은 거절한다.
- [x] 위치 유무와 관계없이 업체 없는 공정이 표시된다.
- [x] 전체 활성 재질·형태·후속 상태를 실제 HTTP로 검사한다.

## 7. 미정 사항

공개 자료가 없는 반입 규격·현재 허가·계약·실시간 수용량은 업체 확인이 필요하다. 국내 PE/PS 압축 베일의 수령 사업장은 별도 근거 확보 전 연결하지 않는다.
