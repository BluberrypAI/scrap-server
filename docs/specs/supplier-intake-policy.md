# 업체 등록 반입조건과 문의 응답

2026-11-17 사용자 확정 요청. 실제 업체 연락 없이 별도 시험 기업으로 웹 검증한다.

- 확인된 시설-기업 연결이 있는 업체만 자기 시설의 반입조건을 등록한다. 임의 시설 소유권 등록은 제공하지 않는다. synthetic 연결은 local/test에서만 허용한다.
- 시설별 버전을 증가시키는 변경 이력을 DB에 저장한다. 내용: 문의 접수 여부, 최소/최대 kg(모르면 null), 반입 재질·형태 설명, 오염·포장·일정 조건, 로트별 필수 확인 조건. 업체 자기신고이며 허가 인증이 아니다.
- GET/POST /workflow/supplier-policies. POST는 facility_key, expected_version, policy. 동시 수정·다른 업체 수정 차단.
- 후보 검토에 당시 업체 조건을 표시하고, 문의/인수 요청에는 스냅샷을 저장한다. 변경 시 후보 재검토 필요. 이전 문의 조건은 임의 변경하지 않는다. 신규 문의 접수 중단 시 새 요청 차단.
- 문의는 응답 대기로 시작한다. 등록한 필수 조건이 있으면 수신자가 조건부 수락을 제시해야 하며, 등록 조건은 자동 포함된다. 발송자 자료 제출과 수신자의 전 조건 확인 전 최종 수락·QR 불가.
- 등록한 물량 범위·오염·포장 조건은 업체 안내로 표시한다. 자동 허가 판정이나 AI 검증 완료로 취급하지 않으며 업체가 개별 물량에 대해 확인한다.
- POST /workflow/offers/{id}/messages: 문의 당사자만 대기/조건부 상태에서 답변. revision 충돌 검사, 최대100메시지·1000자, 발신 기업·시각 저장. 제3자/과거 참여자 접근 차단.
- 웹 기업 데이터 관리에 반입조건 탭, 후보 카드에 업체 직접 등록 조건, 문의 화면에 양방향 답변과 기존 조건부 수락 흐름을 연결.
- 새 모델은 transport 도메인. 기존 API 삭제 없음. 자동 연락·계약·허가 승인 없음.

검증: 소유권·동시 수정·업체 조건 변경에 따른 캐시 무효화·스냅샷 불변·접수 중단·조건 미충족 QR 차단·문의 권한·A/B 별도계정 웹 문의→조건부 수락→자료→수락→QR 입고.
