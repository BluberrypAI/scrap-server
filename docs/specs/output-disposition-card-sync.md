# 처리 결과와 다음 진행 통합 등록

상태: 확정 — 2026-11-20 사용자 지시. T-183.

## 범위

B는 전체 문진을 반복하지 않고 받은 처리 건의 실제 산출물을 기록하며 완료·추가 가공·보관 중을 함께 선택한다. 별도 완료 버튼/폼을 웹에서 제거한다. 보관은 완료와 구분하고 이후 같은 산출물로 추가 가공을 재개할 수 있다. A 목록 카드는 참여 기업의 인계/산출물 변경을 자동 조회한다. 운영 배포·실제 업체 연락·새 법적 분류 확정·DB 구조 변경은 포함하지 않는다.

## API·데이터

- 기존 `POST /api/v1/workflow/lots/{id}/output`에 선택 필드 `next_action`(complete/forward/hold), `completion_reference`, `intended_use`, `completion_confirmed`를 추가한다. 미전송한 기존 클라이언트는 종전 processed 동작 유지.
- complete는 예상과 일치하는 완료 허용 산출물·양수 중량·현재 보유 기업·근거·용도·확인을 검증하고 **산출물과 완료 스냅샷을 한 트랜잭션에 저장**한다. 실패 시 산출물도 부분 저장하지 않는다.
- hold는 문자열 상태 stored(보관 중)와 현재 산출물의 next_action을 저장한다. 추가 가공은 processed, 완료는 completed. 기존 JSON·문자열 컬럼 사용, 마이그레이션 없음.
- 새 `POST /api/v1/workflow/lots/{id}/output-action`은 processed/stored의 현재 기업만 revision을 대조해 같은 산출물의 진행 방향을 바꾼다. 보관 중에는 기존 후보 조회/인계 상태 검증으로 새 인계를 차단한다. 변경은 새 공정/산출물 기록을 만들지 않는다.
- `POST /finish`는 기존 클라이언트를 위해 유지하고 동일 완료 검증을 공유한다. 기존 필드·형식 삭제 없음. 인증·타 기업·버전·예상 불일치 제약 유지.

## 웹

산출물 등록 폼에서 다음 진행을 필수 선택한다. 완료 시 기존 근거 입력을 재사용하고 용도·완료 확인만 추가한다. 보관/이미 기록된 결과의 진행 변경은 해당 결과 카드에서 처리한다. 추가 가공일 때만 현재 상태 기준 후보 검토를 보여 준다. 신규 입력에서 기존 별도 종료 폼을 표시하지 않는다.

A 목록은 표시 중 5초 간격, 창 복귀 시 즉시 갱신한다. 응답이 겹치거나 이전 조회가 늦게 돌아와 최신 카드를 덮지 않도록 한다. 일시 오류는 기존 카드를 보존하고 다음 조회로 복구한다. 숨겨진 창 조회·화면 이탈 후 업데이트는 멈춘다. 완료 건의 기존 완료 이력 이동은 유지한다.

## 후속 소재별 회귀 검증 (T-184)

2026-11-20 사용자 지시로 PP·PE·PET·알루미늄까지 범위를 넓힌다. 소재별 완료·추가 가공·보관 선택과 B 종료/C 인계 두 경로를 별도 시험 계정의 실제 웹에서 검증한다. 시험 데이터 준비와 브라우저 수행 범위를 결과 문서에 구분한다. 완료 허용 상태·분류 규칙·업체 능력은 시험을 통과시키기 위해 바꾸지 않는다. 현재 계정 연결은 보존하고 새 연결은 로컬 synthetic임을 표시한다.

검토 후 업체 계정이 연결된 경우 응답의 recipient를 현재 DB로 갱신한다. AI·거리·공정 근거 원본 캐시는 보존하고 추가 모델 호출·revision 변경 없이 표시한다. 삭제된 연결·자기 기업·운영에서 허용되지 않은 synthetic 연결은 수신 계정으로 표시하지 않는다. 인수 요청의 기존 DB·권한 재검사는 유지한다. [703/108 검사·웹 결과와 PE 공백](../material-disposition-validation-20261120.md).
