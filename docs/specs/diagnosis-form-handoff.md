# Spec: 문진의 현재 형태 이어받기

| 항목 | 내용 |
| --- | --- |
| 상태 | 구현 완료 — 사용자가 문진 로직을 바꾸지 않고 기존 출력의 소재·형태를 연결하도록 요청 |
| 관련 기획 | 사용자 요청(2026-11-19), product-plan 4장 확인되지 않은 값 보존 |
| 관련 todo | T-178 |

## 1. 목적

문진에서 이미 현재 형태를 명확히 말했는데도 경로 화면에서 다시 고르는 문제를 해결한다. 분류번호·소재는 기존 확정 인계 객체에서 그대로 읽는다.

## 2. 범위

- 포함: 기존 facts의 알려진 input_form 또는 이미 제공되는 conversation의 명확한 사용자 형태 진술을 받아 기존 허용 형태와 대조. 출처·원문·턴을 함께 표시하고 수정 허용. 불명·복수·예정·부정·과거 진술은 추가 선택 유지.
- 제외: 문진 질문·LLM 추출·법 분류 규칙·엔진 출력 변경, 사진으로 형태/소재 자동 확정, 소재나 분류번호의 추정 변경, 재진행 이전 대화 재활용.

## 3. 요구사항

1. 엔진 출력에 세부 형태 필드는 현재 없고 대화 원문은 있다. 수신 어댑터는 사용자 진술의 제한된 표현만 정규화하고, 애매하면 고르지 않는다. assistant/버튼·문서 안내를 형태 진술로 사용하지 않는다.
2. 확정 결과의 소재·번호·고체 조건을 그대로 검사한다. 같은 의미의 형태 별칭은 해당 소재의 지원 키로 정규화한다. 미지원 형태를 임의 다른 형태로 바꾸지 않는다.
3. 명확한 형태는 웹에 미리 적용하고 원문을 펼쳐 볼 수 있다. 선택 목록은 정보가 없거나 사용자가 수정할 때만 표시한다.
4. 물량 등록에는 기존 필수 input_form을 보낸다. 서버는 같은 원문을 다시 읽고 일치하는 경우 원문 출처를 보존한다. 수동 수정은 사용자 입력으로 구분한다.

## 4. API

| 메서드 | 경로 | 인증 | 설명 | 성공 | 실패 |
| --- | --- | --- | --- | --- | --- |
| POST | /api/v1/diagnosis/cases/{id}/treatment/next-step | 기업 쿠키 | 기존 응답에 selected_form/selected_form_label/form_source/form_quote/form_turn_id 추가 | 200, 기존 ready/needs_input 등 유지 | 기존 401/404/422/503 |
| POST | /api/v1/workflow/lots | 기업 쿠키 | 기존 요청 유지. 전달된 형태의 출처를 기존 JSON에 보존 | 기존 200 | 기존 오류 유지 |

## 5. 데이터

새 테이블·migration·환경변수 없음. 원문은 최대400자만 형태 출처에 사용하며 전체 대화를 새 로그/캐시에 남기지 않는다. 기존 immutable 인계 객체는 변경하지 않는다.

## 6. 완료 조건

- [x] PP·PE·PET·금속 등의 명확한 형태가 코드·소재를 유지한 채 전달된다.
- [x] 소재만 있거나 상충·예정·부정·불명인 형태는 자동 선택하지 않는다.
- [x] assistant/문서/버튼과 재진행 이전 진술은 사용하지 않는다.
- [x] 웹의 자동 적용·수정·누락 시 추가 선택·물량 등록을 확인한다.
- [x] 기존 업체 검토·사진·QR 흐름과 전체 자동 검사에 회귀가 없다.

### 검증 기록 (2026-11-19)

- server 전체679개, 형태 전달 관련35개 통과. Ruff·포맷·에이전트 문서 동기화 검사 통과. Authlib 의존성 경고1건.
- web 전체104개·프로덕션 빌드 통과. 기존 지도 번들 크기 경고는 유지.
- 실제 로컬 웹에서 새 문진에 “PP 사출 잔재” 입력 → 문진6질문·확정 → 번호51-03-01/소재PP 유지 → 경로 화면에 제조 잔재·스크랩 자동 적용 → 형태 수정으로 파쇄품 선택·원래 형태 복구 → 100kg 등록·사진 입력 단계 확인. 수신 계정의 합성 시험이며 실제 거래가 아니다.
- 수신한 형태 진술과 사용자 수정은 source로 구분한다. 조건이 불분명한 모든 자연어를 해석하는 기능은 아니며 모호한 경우 추가 선택을 남긴다.
- scrap-diagnosis의 질문·규칙·LLM·API 코드는 수정하지 않았다. 기존 CaseDetail.conversation만 사용하며 추가 모델 호출은 없다.

## 7. 미정 사항

범용 자연어 형태 판독은 이번 범위가 아니다. 향후 문진에서 별도의 구조화된 형태를 내보내면 어댑터가 우선 사용하되 질문·판정 변경은 별도 담당과 협의한다.
