# Spec: 법정 서식 작성본 (제6호·제12호·제5호)

| 항목 | 내용 |

| 관련 todo | T-166 |

## 1. 목적

문진을 확정한 기업이 폐기물관리법 시행규칙의 현행 서식을 처음부터 손으로 쓰지 않도록, 서버가 아는 값(기업 정보, 확정 판정)과 사용자가 입력한 값을 **원본 한글 서식(HWPX)의 칸에 넣은 작성본**을 만든다. 제출은 사용자가 직접 한다.

## 2. 범위

- 포함
  - 별지 제6호 사업장폐기물배출자 신고서 (2021.7.6 개정): 사업장일반폐기물
  - 별지 제12호 폐기물 처리계획서 (2020.5.27 개정): 지정폐기물
  - 별지 제5호 수탁처리능력 확인서 (2026.11.12 개정): 배출 기업이 쓰는 ①~⑥칸만
  - 칸별 미리보기 목록(어느 칸에 무엇이 들어가는지)
  - 파일 형식: 한글(HWPX, 원본 서식 칸에 값 넣기)과 PDF(인쇄·제출용, 빈 서식 PDF 위에 값 그리기)
  - 제출 칸(제6·12호): 작성일, 받는 기관장, 신고인(제출인) 이름, 서명·날인 이미지(직접 그린 서명 또는 도장 이미지, 한글·PDF 모두)
  - 사용자가 확인해 입력한 분류번호·성질/상태 (엔진 판정보다 우선, 경고로 표시)
- 제외
  - 기관·올바로 제출, 자동 발송, 생년월일 입력, 서명·작성일의 저장
  - 제5호 아래쪽 날짜·서명·받는 기관 (처리 업체(수탁자)가 씀)
  - 입력값·작성본 저장 (DB 변경 없음)
  - 업체 문의서 (vendor-inquiry가 담당), 기관 질의서 (엔진 질의서 재료 API 연결 후 별도 spec)
  - HWP(구형) 파일, Word(DOCX): 정부 배포 Word판이 없고 서버(리눅스)에서 한컴·Word 변환을 쓸 수 없어 별도 결정
  - 판정·분류 추론: 서버는 분류번호를 추론하지 않는다. 엔진 handoff 값 또는 사용자가 직접 입력한 값만 쓴다

## 3. 요구사항

1. 로그인한 기업의 엔진 건을 매번 다시 조회한다. 확정(`CODE_CONFIRMED`)되고 `diagnosis-handoff-v1`인 handoff만 쓴다. 미확정·재개·다른 기업 건은 거절한다.
2. 폐기물 이름·구분은 handoff에서만 가져온다. 분류번호·성질/상태는 handoff 값이 기본이고, 사용자가 `waste.waste_code`·`waste.physical_state`로 직접 입력하면 그 값을 신고인의 기재로 쓴다. 다른 위치(최상위·company)에 보낸 분류번호는 무시한다.
3. 사용자 입력이 없으면 분류번호는 `review == "VERIFIED"`일 때만 넣고, 그 밖에는 칸을 비우고 `warnings`에 판정 번호와 입력 안내를 적는다. 사용자 입력이 판정과 다르면 `warnings`에 둘 다 적는다.
4. 사실(`facts`)은 `UTTERANCE`·`DOCUMENT` 등 확인된 출처만 쓴다. `DERIVED`(추정)이거나 값이 애매하면 칸을 비운다(사용자가 고르면 그 값).
5. 서식별 대상: 제6호는 `GENERAL`만, 제12호는 `DESIGNATED`만. 맞지 않으면 422.
6. 기업 정보(상호, 주소, 업종, 주 생산품)는 server 기업 프로필에서 기본값을 가져오고, 사용자가 요청 본문으로 덮어쓸 수 있다. 서식에만 쓰는 칸(사업자등록번호, 대표자, 전화번호, 산업단지명, 배출량, 운반·처리 정보 등)은 요청 본문으로 받는다.
7. 처리방법 번호는 제5호 3쪽 코드표에 있는 번호만 받고, 처리구분(자가 1xxx / 위탁 2xxx)과 맞아야 한다.
8. 원본 서식 칸의 원래 글자를 확인한 뒤 값을 넣는다. 서식 파일이 바뀌어 칸이 어긋나면 500이 아니라 명확한 오류로 멈춘다.
9. 응답은 `Cache-Control: no-store`. 서버에 파일·로그로 입력값·서명을 남기지 않는다.
10. 제출 칸(제6·12호만): 작성일은 `YYYY년 M월 D일`. 받는 기관장은 서식에 인쇄된 대상 중 하나여야 한다(제6호: 특별자치시장·특별자치도지사·시장·군수·구청장으로 끝남, 제12호: 도지사·시장·환경청장으로 끝남). 비우면 인쇄된 목록을 그대로 둔다. 신고인 이름을 비우면 대표자 성명을 쓴다.
11. 서명·날인: 브라우저에서 그린 서명 또는 도장 이미지(PNG `data:image/png;base64`, 200KB 이하, `mark_type`: `signature`·`seal`)를 "(서명 또는 인)" 자리에 넣는다. 크기는 서명 약 1cm, 도장 약 1.6cm 높이(한글 파일은 그 0.75배). PDF는 측정한 위치 가운데에, 한글 파일은 그 줄 오른쪽 끝에 글자 앞(떠 있는 그림, 서식 배치는 그대로)으로 넣는다. `signer_confirmed`(신고인 본인 또는 위임받은 사람이 직접 서명·날인함)가 없으면 거절한다. 제5호에는 받지 않는다.

## 4. API

| 메서드 | 경로 | 인증 | 설명 | 성공 | 실패 |
| --- | --- | --- | --- | --- | --- |
| POST | `/api/v1/diagnosis/cases/{id}/legal-forms/{kind}/preview` | 필요 | 칸별 값 목록과 경고 | 200 `{kind, title, filename, edits[], warnings[], problem}` | 401, 404, 409(`CASE_NOT_CONFIRMED`), 503(엔진) |
| POST | `/api/v1/diagnosis/cases/{id}/legal-forms/{kind}?format=hwpx\|pdf` | 필요 | 작성본 파일 (기본 hwpx) | 200 `application/hwp+zip` 또는 `application/pdf`, `Content-Disposition` | 위와 같음, 422(서식 대상 아님·입력 문제·지원하지 않는 형식) |

- `kind`: `form6` / `form12` / `form5`
- 요청 본문: `{company?: {...}, waste?: {...}, submit?: {date, recipient, signer_name, signature_png, mark_type, signer_confirmed}}` (필드 목록은 OpenAPI 스키마)
- preview의 `edits[]`: `{slot, cell, op, show, place?, pattern?, before?, after?}`. `op: "sign"`은 서명 이미지 자리, `place: "at"`은 측정한 위치에 그대로 쓰는 값이다. 웹은 미리보기 그림의 칸 위치(`slot`)에 `show`를 그린다. `sub`는 칸 안 줄에서 `pattern`(정규식)에 맞는 부분을 `before + show + after`로 바꾼 모습이다
- preview는 서식 대상이 아니거나 입력 문제가 있어도 200으로 `problem`에 문구를 담고(입력하는 동안 바로 보여 주기 위해), 파일 API는 422로 거절한다
- 서식 칸 원래 글자가 다르면(서식 파일 교체 실수) 파일 API는 500 `INTERNAL_ERROR`로 멈춘다

## 5. 데이터

새 테이블·마이그레이션 없음. `app/domains/legal_forms/resources/`:

- `<kind>-<개정일>.hwpx`: 국가법령정보센터 현행 서식을 한컴오피스로 HWPX 변환
- `<kind>-blank.pdf`: 같은 HWPX를 한컴오피스로 PDF 변환한 빈 서식 (작성 방법 쪽 포함)
- `<kind>-layout.json`: 첫 쪽 칸별 위치(pt, 왼쪽 위 기준). `scripts/legal_forms_layout.py`(Windows + 한컴오피스 + PyMuPDF, 개발용)로 측정. 서식이나 칸 규칙을 바꾸면 다시 만들고, 웹 미리보기 자료(scrap-web `public/legal-forms/`)도 같이 바꾼다

PDF 글자: `resources/fonts/*.ttf`(공개 라이선스 한글 글꼴)가 있으면 넣어서(embed) 만들고, 없으면 표준 한글 글꼴(HYGothic-Medium)을 참조만 한다. 참조만 하면 보는 프로그램에 따라 숫자·하이픈 간격이 달라 보일 수 있다.

## 6. 완료 조건

- [x] 미로그인·다른 기업·미확정 건은 작성본을 만들지 않음
- [x] 제6호에 지정폐기물, 제12호에 일반폐기물 건을 넣으면 422
- [x] VERIFIED 아닌 판정은 분류번호 칸이 비고 경고가 있음
- [x] DERIVED 사실은 서식에 들어가지 않음
- [x] 브라우저가 보낸 분류번호는 무시됨
- [x] 처리구분과 맞지 않거나 코드표에 없는 처리방법은 422
- [x] 만든 HWPX가 zip 규칙(mimetype 첫 항목·무압축)을 지키고, 넣은 값이 해당 칸에 있음
- [x] 서식 칸 원래 글자가 다르면 명확한 오류
- [x] 응답에 no-store
- [x] PDF는 빈 서식 쪽 수를 그대로 두고 첫 쪽에 값을 그림, 모든 칸 규칙에 위치 자료가 있음
- [x] `format=pdf`는 PDF·`.pdf` 파일 이름, 지원하지 않는 형식은 422
- [x] 작성일·받는 기관장·신고인 이름이 제6·12호의 해당 줄에 들어감. 인쇄된 대상이 아닌 기관장은 거절
- [x] 서명·날인은 본인 확인 없이는 거절, PNG만, 제5호 거절, 한글 파일(BinData·목록·그림 태그)과 PDF 모두에 들어감
- [x] 사용자가 입력한 분류번호·성질/상태가 쓰이고, 판정과 다르면 경고

## 7. 미정 사항

- product-plan 범위 포함 여부 (사람 결정)
- 서명 이미지가 기관에서 서명으로 인정되는지: 전자서명법 제3조상 전자적 형태라는 이유만으로 효력이 부인되지는 않지만, 제출 기관이 자필 서명·날인을 요구할 수 있다. 화면에서 제출 전 확인을 안내한다
- 기업 프로필에 사업자등록번호·대표자·전화번호·산업단지명을 저장할지 (지금은 요청마다 입력)
- 미리보기 그림·칸 위치 자료를 웹 정적 파일로 둘지
- PDF에 넣을 한글 글꼴 파일(공개 라이선스) 추가 여부
- Word(DOCX) 지원 방식
