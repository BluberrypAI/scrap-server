# 문진 확정 결과 → 첫 공정·업체 검토 연결

- 상태: 구현 및 로컬 통합 검증 완료 (실제 반입 승인 제외)
- 관련 기획: 사용자 요청(최신 팀 문진을 실제 업체 후보·AI 검증까지 연결), 기존 diagnosis-engine-integration / treatment-registry
- 기존 계약 필드와 API는 유지하고 새 연결 API만 추가한다.

## 범위와 API

로그인한 기업의 엔진 건을 매번 다시 조회한다. POST `/api/v1/diagnosis/cases/{id}/treatment/next-step`과 `/treatment/intake-reviews`는 `{input_form?: string}`만 받는다. 분류번호·재질·기업 ID·R코드를 브라우저에서 받아 신뢰하지 않는다. 현재 유효한 확정 handoff만 쓰고, 재개·미확정·다른 기업의 건은 후보를 제공하지 않는다.

원래 문진의 material과 physical_state, GENERAL / WASTE_CODE / RECOMMEND_ROUTE를 확인한다. 구체적 현재 형태는 기존 문진 사실에 없으므로 사용자가 별도로 확인한다. 현재 카탈로그의 지원 조합만 제시하며, R코드는 null(미확인)로 유지한다. R코드 미확인은 법적 허용의 의미가 아니며 공정 조사와 AI 근거 확인만 가능하다. 지정·비폐기물·미지원 소재는 자동으로 일반 재활용 공정에 넣지 않는다.

회사 위치는 server 기업 프로필 좌표를 쓴다. 좌표가 없으면 거리 순위를 만들지 않는다. 응답에 판정 버전·규칙 검토 상태·추정 항목과 미확인 R코드를 보존한다. AI에는 기존 공개 근거 요약만 전달한다. 공개 근거 검토는 실제 인수·허가 승인으로 승격하지 않는다.

## 데이터 / 제외

새 DB 테이블이나 스키마 변경 없음. 엔진 건은 기존 엔진 DB에서 영속화된다. server wastes 복사와 확정 이후 B→C 운송 변경은 이번 연결에서 제외한다. 웹은 서버 문진 목록과 건 ID로 다시 열며 로컬 가짜 분류번호를 만들지 않는다.

## 완료 조건

- [x] 사용자 위조 코드·R코드·좌표를 거절
- [x] 공정 후보 전부를 기존 AI 검토기에 전달하고 비밀/기업 위치를 제외
- [x] 웹에서 문진→확정→형태 확인→공장 표시→근거 검토→새로고침 재진입 확인

## 한계

문진 규칙은 UNVERIFIED 표시를 유지한다. 시험성적서 자동 추출, 실제 반입 허가 검증과 실제 거래는 이번 확인 범위가 아니다.
