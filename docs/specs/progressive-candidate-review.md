# 도로거리 순차 선별과 검토 진행 표시

상태: 확정 — 2026-11-19 사용자가 예정 경로·AI 최적화·orb 진행 표시 구현을 직접 요청했고, 이후 전체 검토 대신 도로거리 상위 5곳부터 검토·보충하도록 범위를 수정함.

## 범위

- 후보는 기존 분류·공정·현재 상태로 조회한다. 카카오 자동차 도로거리가 확인된 사업장을 거리순으로 검토한다.
- 가까운 서로 다른 사업장 5곳부터 검토하고, 공개 투입 근거가 부족하거나 제한·모델 미완료인 후보가 있으면 다음 사업장을 검토한다. 최대 5개 사업장을 표시하며 부족하면 확인된 수만 표시한다.
- 미검토·근거 부족·거리 미확인 후보를 삭제하거나 부적합으로 단정하지 않는다. 별도 확인 목록과 개수를 제공한다.
- 사진은 물량 단계에서 한 번 관찰하고 후보 전체에 같은 관찰을 사용한다. 사진·모델·관찰 지침이 바뀌면 재관찰한다. 비폐기물 사진은 업체 비교 전에 차단한다.
- 업체별 응답은 그 업체의 입력·근거·모델 버전이 같은 경우 재사용한다. 한 업체 답변이나 거리 변경으로 다른 업체 판단을 무효화하지 않는다.
- DB에 검토 작업·단계·실제 완료 수를 저장하고 웹은 짧은 요청으로 시작·조회한다. 새로고침 후에도 진행 상태를 복원한다.
- 인수 요청/조건부/수락 단계부터 A·B 핀과 계산한 예정 도로 경로를 표시한다. 운송 시작·QR 입고 상태와 구분하며 거절·취소된 요청은 예정 경로에서 제외한다.
- 실제 GPS, 허가 확정, 자동 수락, 화물차 전용 경로, 사진으로 분류번호 변경은 범위 밖이다.

## API (기존 형식 유지, 추가만)

- POST `/api/v1/workflow/lots/{id}/review-jobs`: 기존 revision을 검사하고 작업을 저장, 202로 처리 건과 실제 진행 정보를 반환. 동일 처리 건의 실행 중 중복 요청은 같은 작업을 반환.
- GET `/api/v1/workflow/lots/{id}`: 기존 응답에 `review_progress`를 추가. 참여 기업만 조회 가능.
- 기존 POST `.../candidates`는 기존 전체 후보 동기 응답을 호환 유지한다. 새 웹은 `review-jobs`로 거리순 5곳 선별·캐시·진행 조회를 사용한다.
- GET `.../road-route`: 기존 segments에 인수 요청·수락 대기의 예정 구간을 포함. `phase` 필드를 추가하고 취소·거절 구간 제외.
- route 내부 서비스: 검토 버전 조회 및 사진 단독 관찰 API 추가. 브라우저는 route를 직접 호출하지 않는다.

## 저장과 실패 처리

기존 workflow_lots JSON에 제한된 검토 작업·캐시를 저장한다. 원본 이미지·키는 캐시에 넣지 않는다. 업무 revision은 진행률 갱신만으로 변경하지 않는다. 변경된 물량의 과거 작업은 결과를 덮어쓰지 않는다.

DB 잠금으로 작업을 하나만 가져오는 워커를 앱 수명주기에서 실행한다. 중단된 작업의 lease 만료는 중단 상태로 표시하고 완료된 후보 결과는 보존한다. 모델 시간초과는 사용자 재시도 대상으로 남기며 자동 승인하지 않는다.

웹 orb는 서버 단계(candidate_search/road_distance/photo_observation/facility_review/saving/completed/failed/interrupted)에 따라 안내를 바꾼다. 경과 시간만으로 단계를 만들어내지 않는다. 모션 축소 설정을 지원한다.
