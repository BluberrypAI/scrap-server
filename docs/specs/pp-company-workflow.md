# PP 기업 간 인계·처리 완료

사용자의 2026-11-12 명시 요청: 현재 상태·사진을 보내 수신 기업이 수락/거절하고, PP A→B 종료 및 A→B→C 완료를 별도 기업 계정으로 웹 검증한다. 기존 API를 변경하지 않는 transport 도메인 추가 구현이다.

확정 문진에서 server Waste와 영속 로트를 생성한다. PP 잔재/파쇄품과 양수 중량·상태 설명을 받는다. 사진은 제한 크기로 검증·재인코딩하고 기업 참여자에게만 제공한다. 2026-11-13 사용자 요청에 따라 후보 검토 시 현재 단계 사진과 상태 설명을 AI 서비스 → Azure에 전달한다.

상태: 준비→수락 대기→수락/거절→QR 입고→처리 결과→다음 인계 또는 완료. 현재 담당 기업만 다음 업체 요청·산출물 기록·종료할 수 있다. A는 전체 진행 조회 가능. 동시 변경은 버전 검사와 행 잠금으로 차단한다. 수락 전 QR 발급, 입고 전 처리, 산출물 없이 C 조회·완료를 차단한다.

후보는 기존 공정 API를 재사용하되 저장된 실제 산출물만 사용한다. 전체 후보 AI 검토를 저장하며 업체 수락과 AI 판정은 구분한다. 수락은 해당 로트의 업무상 수락이며 현행 허가 검증 완료가 아니다. 별도 확인 항목을 수신자가 선언하고 근거 참조를 기록한다.

기존 기업과 시설 연결은 DB의 검증된 계정 바인딩을 통해서만 한다. 로컬 테스트 기업은 가상으로 명시하며 실제 사업장을 사칭하지 않는다. 로컬에서만 합성 바인딩을 허용하고 운영 시 실제 시설 증빙 검증이 필요하다.

완료는 카탈로그 종료 플래그만으로 정하지 않는다. 현재 업체가 실제 산출물·중량·품질/용도 설명·완료 근거를 기록하고 단계 종료를 확인한다. PP 파쇄품은 이 MVP의 최종 완료로 인정하지 않고 펠렛/컴파운드 산출물만 완료 신청 가능. 법적 재활용 인증과 구분한다.

검증: 인증·기업 격리·거절·버전 충돌·입고 전 처리 차단·사진 접근제어·실제 산출물 기반 C 후보 전체 검토·A 모니터링·두 웹 시나리오. 사용자 요청으로 구현 승인된 범위이며 product-plan 원문은 수정하지 않는다.

## API와 저장

모든 경로의 접두사는 `/api/v1/workflow`다. 인증된 기업과 로트 참여 권한을 확인한다.

| 경로 | 역할 |
| --- | --- |
| POST /lots, GET /lots, GET /lots/{id} | 확정 문진으로 생성, 참여 건 목록·상세 |
| POST /lots/{id}/photos, GET /photos/{id} | 현재 단계 사진 첨부·참여 기업 조회 |
| POST /lots/{id}/candidates | 저장된 현재 형태·중량·처리 이력으로 후보 전체 AI 검토 |
| POST /lots/{id}/offers | 선택한 업체에 현재 상태·사진·AI 검토 스냅샷 전달 |
| GET /offers/{id}, POST /offers/{id}/decision | 인수 내용 조회, 수신 기업 수락/거절 |
| POST /offers/{id}/qr, POST /offers/{id}/receive | 발신 기업 QR 발급, 지정 수신 기업 입고 |
| POST /lots/{id}/output, POST /lots/{id}/finish | 실제 산출물 입력, 최종 완료 |

서버는 `workflow_lots`, `workflow_offers`, `workflow_photos`, `workflow_facility_accounts`를 기존 wastes·route_steps·qr_field_checks·완료 스냅샷과 연결한다. 브라우저 저장소를 기업 간 공유 원장으로 사용하지 않는다.

현재 상태에는 `state_key`, `mass_kg`, `condition`이 있고 실제 산출물에는 미확인 가능한 `purity_percent`, 근거 `evidence`를 추가한다. 변경 요청은 `revision`을 대조한다. 수신 요청 스냅샷은 발신자의 다음 변경으로 덮어쓰지 않는다. 사진 변경 시 이전 후보 검토를 무효화한다. AI 호출 실패 캐시는 재시도 가능하다.

사진은 3MB·1600만 화소 이하 JPEG/PNG/WebP를 검사하고 최대 1600px JPEG로 재인코딩한다. 단계당 4장, 메타데이터 제거, 참여 기업만 조회, 응답은 no-store다. 현재는 DB 바이트 저장이며 자동 보관 만료·삭제 정책은 미정이다.

## 상태·사진 기반 후보 검토 (사용자 요청으로 승인된 확장)

DB 공정 후보 생성은 유지한다. 서버가 현재 단계의 형태·중량·상태 설명·기록된 순도·재인코딩 사진만 AI에 전달하며, AI 레포가 Astra를 호출한다. 과거 단계 사진·계정·QR·원본 파일명·EXIF는 전달하지 않는다. 사진/설명에는 기업 고유 정보가 포함될 수 있어 화면에 Azure 전송을 알린다.

후보별 공개 반입 근거와 별도로 `lot_review`에 사진 관찰, 사용자 설명 기반 주의점, 추가 질문, 고정 미확인 항목을 반환한다. 사진의 화학 성분·정확한 재질·순도·유해성·중량 추론은 금지한다. 설명은 사용자 진술이지 확인 사실이 아니다. 사진 속 문구와 설명의 지시문을 실행하지 않는다. 출처가 잘못되거나 응답이 누락되면 검토 미완료로 처리한다. 사진/설명만으로 공개 반입 근거가 확인됐다고 판정하지 않는다.

공개 근거 검토와 물량 검토가 끝나야 인수 요청을 보낼 수 있다. 추가 확인사항이 있다는 이유로 자동 탈락시키지는 않으며 최종 수락은 업체가 한다. 기존 수락·QR·완료 상태를 AI가 바꾸지 않는다. A→B와 B→C 동일 적용, 사진 변경과 실제 산출물 변경 시 검토 갱신. 이전 버전 검토 캐시는 재사용하지 않는다.

완료 조건: 사진·설명 실제 모델 전송, 후보별 결과 유지, 알 수 없는 사항 표시, 잘못된 인용/사진 ID 거절, 사진 없는 설명 검토, 모델 오류 시 인수 요청 보류, 현재 단계 사진만 전달, 기존 두 인계 흐름 회귀 검사.

2026-11-13 보강(사용자 요청): AI는 사진만 보는 관찰 호출 후 고정 관찰·상태 설명·업체 공개 근거를 비교하는 호출로 분리한다. 관찰 호출에는 업체·소재 진술·상태 설명을 보내지 않는다. `photo_observations[].visibility`, `concerns[].category`, `lot_review.observation_method`를 추가하며 기존 필드와 `version=lot-vision-v1`은 유지한다. 서버 검토에는 `analysis_version=isolated-vision-v2`를 추가하여 이전 결과를 재사용하거나 요청 근거로 삼지 않는다. 새 AI 응답이 아니면 미완료로 취급하며 업체 최종 수락·QR 의미는 바꾸지 않는다. 두 단계 최대 80초씩을 감안해 내부 HTTP 대기 한도는 175초다. 웹/게이트웨이 운영 시간제한과 작업 큐 이전은 별도 운영 과제다.

확인사항 구분: cleaning, sorting, drying, testing, facility_evidence, description_conflict, other. 이는 문의 항목이며 검증된 반입 규격이나 자동 탈락 조건이 아니다. 판독 제한·실물이 아닌 사진은 추가 촬영 필요를 명시한다. 사진 관찰 오류·누락·모델 실패 시 업체 비교를 중단하고 재시도 가능하게 둔다.

QR 원문은 발급 응답에만 반환하고 DB에는 해시·만료 시각을 저장한다. 7일 만료, 재발급 시 이전 토큰 무효화, 입고 시 토큰 폐기. 수락 전 발급 및 다른 기업의 입고를 차단한다.

검증 결과와 남은 한계는 [PP 기업별 검증 기록](../pp-company-e2e.md)을 따른다. 실제 허가나 분류번호의 법적 정확성이 검증됐다는 뜻은 아니다.

## 재질 확장: PP·PE 필름·알루미늄캔 (2026-11-14 사용자 요청)

로트 생성 범위를 문진(scrap-diagnosis)이 처리경로 재질을 넘기고 처리경로(scrap-route)가 첫 공정·AI 반입 검토를 지원하는 교집합으로 넓힌다. PET병은 문진이 51-03-01로 판정하고 서버 첫 공정 프로필은 51-03-07만 받아 이번 범위에서 제외한다.

| 재질·형태 (`input_form`) | 분류번호 | 시작 상태 | 완료로 인정하는 실제 산출물 |
| --- | --- | --- | --- |
| PP 사출 잔재 (`scrap`) | 51-03-01 | pp-scrap | pp-pellet, pp-compound |
| PP 파쇄품 (`shredded`) | 51-03-01 | pp-shredded | pp-pellet, pp-compound |
| PE 필름 (`film`) | 51-03-01, 51-03-07 | pe-scrap | pe-pellet, pe-compound |
| 알루미늄 음료캔 (`can`) | 51-29-03 | al-used-can | al-sheet, al-sheet-ingot |

- API 필드 이름·타입은 유지하고 허용 값만 넓힌다. `POST /lots`의 `input_form`에 `film`, `can`을 추가하고, `POST /lots/{id}/output`의 `state_key`는 고정 목록 대신 로트 재질의 등록 상태인지 참조 자료로 확인한다(아니면 422).
- 후보 조회는 로트에 저장된 문진 재질(`data.initial.material`)을 사용한다. 기존 PP 로트는 그대로 동작한다.
- 파쇄품(PP·PE)은 카탈로그 종료 표시와 관계없이 최종 완료로 인정하지 않는다.
- 지원하지 않는 재질·형태 조합의 로트 생성은 409로 거절한다.
- 로컬 시험 계정: `al-can@example.com`을 novelis-yeongju, ulsan-aluminium에 합성 연결한다. PE는 PP와 같은 업체 연결을 쓴다.
- PE 필름은 공개 반입 예시에 필름이 없어 AI 검토가 근거 부족으로 나올 수 있다. 인수 요청은 가능하며 최종 수락은 업체가 한다. PE·알루미늄 실제 웹·Azure 검증은 아직 하지 않았다.
