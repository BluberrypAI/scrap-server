# Spec: 후보별 근거 부족 사유와 엔진 연결 재검증

상태: 확정 — 2026-11-16 사용자 요청. 관련 작업: T-154.

## 범위

기존 252회 검토의 자료를 재점검하고, 공개 사업장·투입 형태 근거를 보강한다.
일반 PET의 51-03-01과 포장재 PET의 51-03-07은 문진 번호를 바꾸지 않고 연결한다.
기업이 저장한 실제 사업장 좌표를 경로 조회에 사용한다. 허가·현재 수용 여부는 추정하지 않는다.

## 계약

route의 기존 반입 검토 응답과 server의 IntakeResult에 선택적 `evidence_gaps: string[]`를 추가한다.
기존 응답은 빈 배열 기본값으로 호환한다. 열거값은 source_missing, site_scope_unverified,
input_form_unproven, material_unproven, output_only, process_unproven,
source_context_conflict, citation_invalid, unspecified다.
모델의 근거 부족 분류와 코드의 인용·범위 검사를 기록하며, 모델의 내부 추론은 저장하지 않는다.
기존 status, 반입 승인, 수신 기업 수락 조건은 그대로다. 새로운 엔드포인트·DB 테이블은 없다.

PE 폐비닐 압축 베일은 `film-bale`로 일반 베일과 분리한다. EPS 부표(51-03-05)의 eps 상세,
철드럼(51-29-04)의 ferrous 상세는 원래 번호를 보존한다. 해당 공정의 현재 허가·이번 물량 인수는 별도다.
PET병 표기(`폐PET병`, `PET 병`, `폐페트병`, `PET bottles`)는 두 PET 코드 모두에서 인용 형태 검사를 통과할 수 있어야 한다.
Azure 대기 80초, server 텍스트 배치 95초, nginx 600초. HTTP 429의 짧고 유효한 Retry-After에만 시간 예산 내 1회 재시도한다.

## 완료 조건

- [ ] 기존 252회와 업체·연결 고유 수를 구분하고, 원래 저장되지 않은 사유를 복원했다고 주장하지 않는다.
- [x] 신규 검토에 사유가 보존되고 잘못된 인용·사업장 범위는 그대로 차단된다.
- [x] 공개 투입·공정·사업장 근거가 확보된 연결만 추가하고 나머지 조사 결과도 남긴다.
- [x] 두 PET 코드, 기업 좌표 저장·변경, 세부 재질 및 후보별 AI 전달을 통합 검사한다.
- [ ] 실제 문진 및 실제 Azure 검토를 재실행하고 성공·보류·오류를 구분한다.
