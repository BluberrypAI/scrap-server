# 사진·상태 설명 불일치 확인

상태: 확정. 2026-11-17 사용자 요청: 불일치 시 확인/수정 뒤 인수 요청, 분류번호 유지, 재문진 안내, 실제 웹 검증.

## 범위
- 현재 물량의 AI 검토 중 하나라도 description_conflict이면 모든 업체 인수 요청을 보류한다. 단순 판독 불가/오염 의심은 명확한 불일치와 구별한다.
- 현재 보유 기업만 상태 설명을 수정하거나 불일치를 확인할 수 있다. 확인은 사유와 기존 문진의 재질·발생 공정이 같다는 명시적 체크를 요구한다.
- 설명 수정 시 기존 AI 검토와 확인을 무효화하고 재검토한다. 확인만 하는 경우 기존 AI 우려는 유지하며 업체에 확인 사유도 전달한다. 확인은 AI 판정/허가/수신 업체의 최종 수락을 대체하지 않는다.
- 확인은 현재 단계·현재 물량·현재 검토에 한정. 새 사진/산출물/재검토 후 재사용 불가. 새 문의에 당시 확인 내역을 저장한다.
- 분류번호·R유형·문진 원본은 변경하지 않는다. 재질·발생 공정·유해성 답변이 달라지거나 불확실하면 새 문진 필요를 안내한다. 사진만으로 재분류하거나 새 문진을 기존 건에 자동 적용하지 않는다.

## API / 데이터
- POST /api/v1/workflow/lots/{key}/photo-conflict-resolution: 기업 인증. revision, action(correct|confirm), condition(수정 시), note(확인 사유), classification_unchanged(확인 시 true).
- 성공 200 기존 lot 응답 + photo_conflict_gate(issues,blocked,resolution). 403 소유권, 409 상태/버전/검토 부재, 422 입력 미달.
- 기존 WorkflowLot.data JSON에 확인 기록 저장, events에 변경 내역, WorkflowOffer.data에 확인 스냅샷 저장. 테이블/기존 API 삭제 없음.

## 2026-11-18 무관 사진 예외 처리 (사용자 요청)
- AI 사진 관찰에 `not_waste`가 하나라도 있으면 모든 인수 요청을 차단한다. 설명 확인·수정으로는 이 차단을 해제할 수 없다. `limited`는 무관 사진으로 단정하지 않는다.
- 현재 보유 기업이 준비/처리 결과 기록 상태에서 현재 단계 사진을 교체한다. 기존 POST /lots/{key}/photos의 선택적 multipart 필드 `replace_photo_id`, `revision`을 사용한다. 교체 시 revision 필수, 기업·단계·상태를 검증한다.
- 원본 사진은 이력 보존을 위해 남기고 data.excluded_photo_ids에 제외를 기록한다. photos 응답에 active 불리언을 추가한다. 현재 검토와 새 인수 요청에는 활성 사진만 포함하며 이전 요청 스냅샷은 유지한다.
- 교체는 기존 AI 검토를 무효화한다. 사진 4장 제한은 활성 사진 기준이며 다른 기업·지난 단계·오래된 revision의 교체를 거부한다.
- 웹은 무관 사진 재촬영 안내와 교체 버튼을 제공한다. 후보 선택/인수 요청 대신 안내를 보여주며, 교체 후 다시 AI 검토한다. 분류번호는 유지한다.
