# 업체 반입조건 B→C 연결과 두 후보 시간초과 보강

## 두 곳이 미완료였던 이유

이전 A→B 시험의 대운프라스틱 나주·중일머티리얼즈 인천은 공개 근거 부족 판정이 아니라
모델 요청의 시간초과로 검토 응답 자체를 받지 못했습니다. route 로그의 실패 분류는
`provider_timeout`이었으며, 두 업체를 함께 비교하던 한 호출이 둘 다 미완료로 만들었습니다.

물량 검토를 업체당 하나의 호출로 나눴습니다. 동시 호출은 3개로 제한하고, server도
로트 후보를 3곳씩 전송합니다. 사진이 있으면 같은 묶음 안에서 독립 관찰을 한 번 공유합니다.
기존의 사진 관찰 80초+비교 80초가 server의 HTTP 175초 안에 들어오도록 했습니다.
사진 없는 공개 근거 전용 요청의 기존 5곳 형식은 유지합니다.
실패 응답을 성공으로 바꾸거나 시간초과 요청을 자동으로 계속 반복하지 않습니다.

같은 합성 PP 사출 잔재 1,000kg 입력으로 실제 Azure 재검증:

| 업체 | 재검증 | 물량 검토 | 해석 |
| --- | --- | --- | --- |
| 대운프라스틱 나주 | 공개 공정 근거 확인 | 완료 | 실제 허가·수분·순도·인수 여부는 별도 |
| 중일머티리얼즈 인천 | 추가 근거 필요 | 완료 | 공개 PP 배터리 케이스 원료 설명만으로 사출 잔재 반입을 확정하지 않음 |

두 응답은 42.4초에 반환됐습니다. 이미 입고한 A 단계의 과거 검토/인계 기록은 수정하지 않았고
DB 원본 해시가 재검증 전후 같음을 확인했습니다. 이 결과는 별도 재검증 결과입니다.
호출 2/2 완료는 업체 2/2 반입 가능이나 앞으로의 시간초과 0건을 뜻하지 않습니다.

## B→C 실제 웹

localhost:5178, A/B/C는 서로 다른 개발용 기업 계정입니다. 실제 업체 연락·실물 운송 없이
같은 합성 처리 건을 이어갑니다. 사진 없이 등록 조건·문의·확인·권한·입고 연결을 시험합니다.

1. C가 **기업 데이터 관리 → 반입조건**에서 독산 화성 시험 연결에 조건 1차를 저장했습니다. 재질은 PP 파쇄품, 물량 범위는 100~1,500kg이며 수분·이종재질 자료, 밀봉 포장·입고일 두 조건을 등록했습니다.
2. 기존 A→B 입고 건에서 B가 산출물 **PP 파쇄품 950kg**과 합성 작업일지 번호를 기록했습니다. 최초 A 1,000kg과 구분되며 순도는 모름(null)을 유지했습니다.
3. B가 다음 업체 검토를 실행해 **9/9 Azure 검토 완료**를 확인했습니다. 공개 근거 확인 1/추가 확인 8이며 물량 검토는 9/9 완료입니다. 조회 기준은 B 사업장·현재 산출물이고, 독산 후보 도로거리 17.7km와 지도 최대 5곳을 표시했습니다.
4. B 화면에 C가 등록한 1차 조건이 그대로 보였습니다. B가 C에 인수 요청과 문의를 보내고, C로 다시 로그인해 문의를 읽고 답변했습니다.
5. C가 조건부 수락을 눌렀고 두 등록 조건이 자동으로 포함됐습니다. C가 수락 메모·허가/규격 확인란을 채워도 자료 확인 전에는 최종 수락이 비활성입니다.
6. B가 조건 하나만 입력했을 때 자료 제출 버튼이 비활성, QR 발급 버튼 없음 확인. 두 조건을 채운 뒤 제출했습니다.
7. C가 제출 자료를 읽고 하나만 확인했을 때 최종 수락은 계속 비활성입니다. 두 조건을 모두 확인한 뒤 최종 수락했습니다.
8. B가 QR을 발급했습니다. A 계정으로 같은 QR 링크를 열면 수신 기업으로 로그인하라는 안내만 보이고 입고 버튼이 없습니다. C로 로그인해 같은 링크에서 입고 확인 성공.
9. A로 재로그인해 **현재 담당 C·950kg·입고 확인 체크·17건 인계 이력·입고 사업장 2곳**을 확인했습니다. C 화면의 물량·확인 사항에도 B→C의 두 조건과 문의/답변, 요청 당시 조건 1차가 보존돼 있습니다.

A는 B→C 진행 상태를 조회하지만 문의 입력·QR 발급을 대신할 수 없습니다.
실제 PostgreSQL에서도 A→B는 processed(조건1/답변1/대화2), B→C는 received(조건2/답변2/대화2),
현재 보유자 C, 검토 출발기업 B를 확인했습니다.

이번 시험은 **C 입고 후 처리 중**까지입니다. C의 최종 산출물·처리 완료는 이번에 다시 실행하지 않았습니다.
휴대전화 카메라 스캔 대신 웹 QR의 복사 링크를 사용했습니다. 실제 업체 연락·운송·허가 확인은 수행하지 않았습니다.

## 자동 검사

- server 전체 531개 통과, Ruff 검사/포맷 통과.
- route 전체 566개 통과·72개 생략·24 subtests 통과. Ruff 검사/포맷 통과.
- 시간초과/JSON 오류/잘못된 형식/중복 응답을 한 업체에 주입해 다른 업체의 결과가 유지됨을 확인.
- 7개 후보의 요청 묶음 3/3/1과 일부 HTTP 실패 시 누락·잘못된 승인 없는 결과 보존 확인.

## 적용

route #65와 server #52를 함께 적용합니다. 새 DB 변경은 없으며, 앞선 반입조건 테이블의
migration `a87485f30805`는 필요합니다. 웹 #53의 반입조건·문의 화면을 사용합니다.
실제 업체 계정의 사업장 권한과 현장 자료 확인은 별도 운영 준비입니다.
