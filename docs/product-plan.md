# Product Plan (server)

> server 레포가 만드는 것과 범위를 정하는 문서. **사람만 수정함.** 에이전트는 읽기만 하며, 범위 밖 요청은 구현하지 않고 사람에게 확인함.
> 원본 기획서는 레포 밖(팀 문서)에서 관리함. 다른 레포의 역할은 [adr/0002-repo-structure.md](adr/0002-repo-structure.md).

## 1. 목적

Re:Source AI(중소 제조기업용 폐기물 처리 의사결정 서비스)의 **회원·기업 정보와 API 관문**을 제공함. frontend는 server만 호출하고, AI 기능은 server가 ai 레포에 요청해 결과를 전달함.

## 2. 사용자

| 구분 | 내용 |
| --- | --- |
| 주 사용자 | 중소 제조기업 폐기물 담당자 |
| 계정 단위 | 기업당 담당자 1명 (기업과 사용자는 1:1) |

## 3. 범위

### 포함

| 영역 | 내용 | 상태 |
| --- | --- | --- |
| 회원 | Google·Microsoft 소셜 로그인, 토큰 갱신·로그아웃 | 구현됨 |
| 기업 | 기업 프로필과 폐기물 프로필 등록·조회 (온보딩) | 구현됨 (수정은 T-010) |
| 분석 연동 | 사용자 입력·문서를 받아 ai 레포에 전달하고 결과를 저장·조회 | 예정. 형식은 ai 팀과 합의 후 spec(T-105)으로 확정 |

### 제외

- 이메일·비밀번호 가입, 기업당 복수 담당자
- 처리 방식 판정, 수치 계산, LLM 호출, 지식 기반 (ai 레포)
- 화면 (frontend 레포), Azure 리소스 정의 (infra 레포)
- 실제 거래·결제·업체 매칭

## 4. 판단 원칙 (구현 시 반드시 지킴)

1. 확인되지 않은 값은 추정해 채우지 않고 비워 둠 (예: 모르는 예상 물량은 null)
2. 판정·계산·LLM 호출은 server에서 구현하지 않음. 필요하면 ai 레포에 요청함
3. 다른 레포(ai, frontend)가 쓰는 API 형식은 필드 추가만 하고, 삭제·이름 변경·타입 변경은 합의 후 진행함
4. 사용자는 소셜 계정(제공자, 고유 ID)으로 식별하며, 이메일로 계정을 합치지 않음

## 5. 용어

| 용어 | 뜻 |
| --- | --- |
| 담당자 | 기업을 대표해 서비스를 쓰는 사용자 1명 |
| 기업 프로필 | 기업명, 사업장 위치, 업종, 담당자 연락처 |
| 폐기물 프로필 | 기업이 주로 배출하는 폐기물의 종류, 발생 주기, 예상 물량 |
