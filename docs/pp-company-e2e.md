# PP 기업별 인계 검증 — 2026-11-13

## 확인한 흐름

확정 문진 → PP 로트 등록(형태·중량·상태·사진) → 후보 전체 AI 검토 → 업체에 인수 요청 → 해당 업체 계정에서 상태·사진 확인 후 수락 → 발신자가 QR 발급 → 수신 업체가 QR 입고 → 실제 산출물 기록 → 다음 업체 조회 또는 완료.

A는 진행 상황과 기업별 인계 기록을 조회한다. 다음 업체는 현재 물량을 가진 기업이 선택한다. B의 처리 결과가 없으면 C를 조회하거나 인계하지 못한다. QR 입고는 재활용 완료와 별도다.

## 실제 웹 시나리오 결과

로컬 웹·서버·문진 엔진·PostgreSQL·Azure 모델을 연결했다. 서로 다른 개발 로그인 계정을 사용했으며, 기업·물량·사진·수락·증빙은 모두 합성 시나리오다. 공개 시설 정보와 계정의 연결도 테스트용이며 실제 업체의 참여나 허가 확인을 의미하지 않는다.

| 시나리오 | 입력 및 처리 | 수신 확인 | 결과 |
| --- | --- | --- | --- |
| A → B에서 종료 | A의 PP 파쇄품 1,000kg → 펠렛 업체 B가 920kg 펠렛 기록 | B 계정의 수락·QR 입고 1회 | 완료. A 계정에서도 확인 |
| A → B → C | A의 PP 잔재 1,000kg → B가 파쇄품 950kg 기록 → C가 펠렛 900kg 기록 | B·C 각각 수락, 서로 다른 QR 입고 2회 | 두 단계 완료. A 계정에서도 확인 |

두 번째 시나리오는 웹 문진을 새로 진행했다. B 후보 3곳, B 처리 후 C 후보 2곳을 실제 Azure 호출로 검토했다. C 계정에 A의 최초 1,000kg이 아니라 B의 실제 파쇄품 950kg과 새 사진이 표시됐다. 파쇄품 기록만으로는 완료 버튼이 열리지 않았다.

직접 종료 시나리오는 기존 확정 문진에서 시작했으며 후보 2곳을 검토했다. QR 이미지는 디코딩해 올바른 인계 주소인지 확인했다. DB에서 단계 완료·수신 QR 기록·기업 분리·사용한 QR 토큰 폐기를 별도로 대조했다.

## 자동 검사

- 서버 전체: 164개 통과. Ruff 통과.
- 신규 기업 인계 검사 7개: SQLite와 별도 PostgreSQL 테스트 DB에서 각각 통과.
- 웹: 34개 통과, Vite 빌드 통과. 기존 큰 번들 경고는 남아 있다.
- 주요 실패 조건: 비참여 기업 접근, 수락 전 QR, 입고 전 처리, QR 재사용·만료·재발급, 오래된 버전, 사진 위장 파일, 거절, 예상과 다른 산출물, 모델 장애 후 재시도.

웹 실행 중 발견한 모델 테이블 등록 누락은 수정 후 다시 진행해 완료했다. 완료 중량이 최초 등록 중량을 덮어쓰는 문제도 수정하고 자동 검사로 최초 1,000kg 보존을 확인했다. 이 마지막 수정 이후 두 웹 시나리오를 처음부터 재실행하지는 않았다. 기존 실행 데이터의 Waste 중량 필드는 920/900kg이며, 인계 스냅샷에는 최초 1,000kg이 보존되어 있다. 후속으로 추가한 기업별 인계 기록 펼치기 화면은 빌드·자동 검사까지 확인했다.

## 남은 검증과 범위

1. 사진: 브라우저 확장 파일 접근 권한으로 자동 파일 선택이 막혀 실제 multipart API로 합성 사진을 넣었다. 수신 업체 웹에서 사진 표시와 단계별 전달은 확인했다. 파일 선택기 자체의 E2E 검증은 남아 있다.
2. QR: 웹의 QR 이미지 디코딩과 별도 기업 로그인 후 입고를 확인했다. 실물 스티커·휴대전화 카메라 시험은 별도다.
3. 법적·현장 판단: 분류 근거의 미검증 상태와 미확인 R코드는 그대로 표시한다. AI 검토나 업체 수락을 허가 검증·정부 인증으로 간주하지 않는다.
4. 현재 완주 검증은 PP 두 사례다. 다른 플라스틱·금속, 모든 PP 성상·오염·지정폐기물 예외의 완전성을 주장하지 않는다.
5. 운영 전 실제 기업-시설 계정 확인, 사진 보관·삭제 정책과 저장소, 계정 탈퇴 시 인계 기록 처리, 동시 사용 부하, 모바일 화면 검증이 필요하다. 개발 로그인은 운영에서 사용할 수 없다.

## 2026-11-13 상태·사진 검토 보강

AI가 사진만 먼저 관찰한 후 상태 설명·업체 근거와 비교한다. 서버는 현재 단계 사진만 전달하고 결과의 관찰 방식과 분석 버전을 보존한다. 기존 `version=lot-vision-v1`은 웹 호환을 위해 유지하며 `analysis_version=isolated-vision-v2`를 추가했다. 예전 검토 캐시나 관찰 방식이 없는 구버전 AI 응답으로 인수 요청하지 못한다. 세척·선별·건조·시험·업체 근거·설명 확인 항목은 문의 분류이며 자동 적합/불합격 판정이 아니다.

서버 전체 168개, 별도 PostgreSQL DB 기업 인계 11개 통과. Ruff 검사·형식 검사 통과. 새 전용 SQLite에서 마이그레이션 upgrade → check → 마지막 migration downgrade → upgrade → check를 확인했다. 기존 웹 완주 이후 이번 보강에서는 자동 회귀/API·모델 검토를 확인했으며 실물 QR·현장 인수를 추가 검증한 것은 아니다.

AI의 실제 PP 세척 전·후 사진 비교, 재현 스크립트와 한계는 함께 올리는 scrap-ai의 `docs/lot-vision-review.md`를 따른다. 원본 연구 PDF·사진, 회사 계정 쿠키·QR 토큰·환경파일은 PR에 포함하지 않는다. 서버·AI 선행 PR을 먼저 병합하고 AI의 새 응답을 배포한 뒤 서버를 연결해야 한다.
