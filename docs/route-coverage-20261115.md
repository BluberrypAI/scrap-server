# 다음 공정 경로 확장·검증 — 2026-11-15

**현재 상태에서 바로 갈 수 있는 등록 공정을 빠뜨리지 않도록 고쳤습니다.** 자료가 없는 업체를 만들어 연결하거나, 막힌 공정을 처리 완료로 바꾸지는 않습니다. 현재 로컬 통합본에 적용했습니다.

## 사용자에게 달라지는 점

1. A의 재질·형태에서 가능한 B 공정을 모두 찾습니다. C까지 완성된 경로가 없다는 이유로 B가 사라지지 않습니다.
2. B가 기록한 실제 산출물에서 C를 다시 찾습니다. A가 정한 예상 산출물로 C를 확정하지 않습니다.
3. 업체가 없는 공정도 단계·근거·확인할 조건을 화면에 남깁니다. 예: PS 베일 → 해체·선별·분쇄. 업체가 없으면 인수 요청은 보류합니다.
4. 회사 위치 기준 지도 Top 5와 전체 검토 범위를 구분합니다. 좌표 미확인 업체도 목록·AI 검토에 남습니다. 거리는 직선거리이며 도로 거리·운송비가 아닙니다.
5. 공정별로 지역을 골라 공개 업체 조사를 할 수 있습니다. PP 외 지원 소재도 같은 검색 API를 사용합니다. 업체명·주소·출처가 반환되더라도 검수 전에는 인계 후보로 자동 등록하지 않습니다.

EPS는 감용 전 상태에서 인고트 수령 업체로 바로 보내지 않습니다. 감용 업체가 없는 첫 단계는 보류하고, 실제 인고트가 확인된 이후에만 기존 인고트 처리 후보를 조회합니다. XPS·난연재를 EPS로 추정하지 않습니다. 신규 사업장 좌표와 현재 반입 조건은 비워 두었습니다.

## 실제 Azure·웹 확인

- 철스크랩 후보 2곳 모두 실제 Azure 검토 요청에 포함했습니다. 대한제강은 `reviewed/form_mentioned`, 한국철강은 `needs_evidence/insufficient`였습니다. 두 결과 모두 `dispatch_approved=false`입니다.
- PE 베일 수도권 검색은 완료됐지만 인용 출처가 검증된 신규 단서는 0건이었습니다.
- PS 베일 동남권 첫 API 검색은 `unavailable`이었습니다. 실제 브라우저에서 재시도해 검색 완료·근거 미발견 안내를 확인했습니다. 실패를 업체 부재로 표시하지 않습니다.
- 웹에서 PS 베일의 공정·확인 조건·지역 선택·검색 상태, 고철 문진의 `ferrous_scrap` 연결·두 사업장 후보 표시를 확인했습니다.
- 웹 검색은 지역·등록 소재·형태·공정만 전송합니다. 기업명·사업장 좌표·사진은 이 검색에 보내지 않습니다. 기존 물량 AI 검토의 전송 범위와 별개입니다.

## 자동 검증

- server: SQLite 413개, 별도 PostgreSQL 시험 DB 413개 통과. Ruff 통과.
- route: 전체 512개 통과·72개 건너뜀·24개 하위 검사 통과. 마지막 검색 문구 변경 후 관련 18개와 Ruff 재확인.
- web: 47개 통과, production build 통과. 기존 3D·지도 청크 크기 경고는 남아 있습니다.
- 회귀 검사는 후속 경로 단절·미리보기 예산 소진에도 직접 후보 유지, 잘못된 완료 순서 거절, 파쇄 상태에서 조기 완료 금지, EPS 감용 전후 구분, 위치 유무와 무관한 공정 표시를 포함합니다.

같은 상위 폴더에 서버·route·web 수정본과 기존 diagnosis·infra를 둡니다. `scrap-infra`에서 실행합니다.

```bash
docker compose -p scrap-full-review up -d --build --no-deps server route web
docker compose -p scrap-full-review exec server python -m app.domains.treatment.import_catalog
```

브라우저 주소는 `http://localhost:5178`입니다. 기업·기존 인계 기록은 유지하며 참조 공정만 갱신합니다. `scrap-server/scripts/audit_live_catalog.py --help`로 조회 검사 옵션을 확인할 수 있습니다. 로컬 증적은 상위 작업 폴더의 `output/verification/route-coverage-20261115/`에 보관했습니다.

## 추가 공개 근거 검증 — T-151

이 절은 위의 최초 결과 이후 수행한 추가 검증이다. **50곳·59개 공정·105개 연결**로
늘었다. 지원 범위의 공정 54개와 연결 100개를 실제 서버 HTTP **198회**로 모두 조회했다.
나머지는 범위 밖 종이 5개다. 플라스틱 입력 49개 중 46개는 후보가 있고 PE 베일 두 번호와
PS 베일 한 번호는 계속 보류다. 조회 가능과 반입 승인은 다르다.

한울메탈 EPS 라인을 연결했고 원문대로 감용물 산출 상태를 따로 저장했다. 일반적인
인고트 공정과 섞지 않아, 감용물→인고트 수령지를 자동 연결하지 않는다. 실제 인고트로
기록해도 예정 산출과 다르면 보류된다. **EPS 첫 수령 후보는 생겼지만 A→B→C 완료를
보장하는 경로는 아니다.** 상세 출처와 PE·PS 조사 결과는
[추가 조사 기록](registry-screen/bale-eps-review-20261115.md)을 참고한다.

- SQLite·격리된 PostgreSQL 시험 DB에서 각각 전체 415개 통과, Ruff 검사·포맷 통과.
- route 전체 512개 통과·72개 환경 의존 검사 건너뜀·24개 하위 검사 통과, Ruff 통과.
- web 47개와 production build 통과. 기존 큰 번들 경고는 유지.
- 신규 EPS 후보를 실제 Azure로 검토: `reviewed / form_mentioned`.
  공개 요약과 업체 투입 형태 대조이며, `dispatch_approved=false`. 사진·실제 물량 검증은 아니다.
- 합성 별도 기업으로 EPS 수락·QR 입고·감용물 보류, 다른 인고트 기록 시 불일치 보류를
  자동 시험했다. 기존 인고트→펠릿 조회·완료와 다른 소재 인계 회귀 검사도 유지했다.
