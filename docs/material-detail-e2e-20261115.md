# 포장재·폐어망·비철 연결과 실제 재검사

2026-11-15. **문진에서 넓은 재질군으로 끝나던 4종을 세부 재질 확인으로 연결했다.** 원래 분류번호를 바꾸지 않는다. 이제 문진 18종 중 13종에서 적어도 한 형태의 첫 업체 후보가 나온다. 세부 재질과 형태를 합친 52개 조합 중 49개에 후보가 있다. 모든 폐기물의 처리업체·반입 조건이 확보됐다는 뜻은 아니다.

## 무엇을 고쳤나

| 문진 결과 | 사용자가 추가 확인 | 연결 결과 |
| --- | --- | --- |
| 플라스틱 포장재 · 51-03-07 | PP / PE / PET | PP 잔재·경질·필름·베일, PE 필름·잔재·경질, PET 병·베일 후보. PE 베일은 업체 근거 부족으로 보류 |
| 폐어망 · 51-03-08 | PA6(나일론 6) | 폐어망 처리 후보 2곳 |
| 기타 수지 · 51-03-01 | SAN / PA66 / PC·ABS | SAN 4형태, PA66 분쇄품·플레이크, PC·ABS 분쇄품·플레이크 |
| 비철 · 51-29-02 | 알루미늄 스크랩 | 별도 스크랩 용해·주조 공정 1곳. 음료캔 공정으로 보내지 않음 |

확인할 수 없거나 혼합물이라면 **모름**을 고른다. 후보를 만들지 않고 확인 필요로 남긴다. 구리·아연·혼합 비철, PE 어망까지 알루미늄·PA6으로 자동 치환하지 않는다. 기존 PP 문진을 다른 재질로 바꾸는 것도 차단한다.

재질을 바꾸면 이전 형태 선택은 초기화한다. 고체 확인·지정폐기물 보류는 그대로 적용한다. 선택값은 원래 문진과 분리해 물량에 저장하며, 같은 값이 다음 업체 조회와 AI 검토에 전달된다.

## 근거를 보강한 부분

여기서 **근거**는 업체 이름이나 명부 등록 사실이 아니라, 어느 사업장에서 어떤 재질·투입 형태·공정을 다룬다고 공개했는지를 확인하는 자료다. 현재 허가·용량·이번 물량 수락은 별도다.

- [울산알루미늄 공식 생산공정](https://ulsanaluminum.com/home/product/product02_01.jsp): 알루미늄 스크랩 → 용해·성분 보정·탈가스·여과·직접냉각 주조 → 슬라브. 공식 사업장 주소와 함께 별도 연결을 추가했다. 외부 폐기물의 현재 수탁 허가나 허용 이물·수분 수치는 확보하지 못했다.
- [정부의 씨엔텍코리아 화성 현장 자료](https://www.mcee.go.kr/home/web/newsRead.do?boardId=1830900&boardMasterId=939&menuId=10607): 폐가전 플라스틱 파·분쇄 사업장 역할을 회사 제품·공정 자료와 대조했다. 화성 전처리 연결 3개만 역할 추정에서 공개 사업장 공정으로 보강했다. 진주 사업장이나 펠릿화 공정까지 확대하지 않았다.
- [창맥 공식 사이트](https://www.changmaec1.com/): 실제 화면에 쓰이는 공개 자료에서 산업용 분쇄 플라스틱 수집·건조·압출과 제품 정보를 재확인했다. JS 자료의 URL·해시를 기록했다. 제품 목록만으로 PA66·PC/ABS의 모든 투입 형태가 승인된다고 보지는 않는다.

현재 참조는 **50개 사업장·60개 공정·106개 공정–업체 연결**, 역할 확인이 남은 연결은 **14개 → 11개**다. 명부 9,604행과 다른 집계다. 이번 변경으로 업체 수가 늘어난 것이 아니라 기존 사업장의 빠진 공정·재질 연결을 보강했다. 자세한 결정은 [역할 재검토 기록](registry-screen/role-review-round4.json)에 남겼다.

## 실제 검사 결과

`웹 프록시 → 서버 → 실제 문진 엔진 → 결과 확정 → 세부 재질·형태 → PostgreSQL → 후보 전체 Azure 검토`

| 검사 | 결과 |
| --- | --- |
| 실제 일반 문진 | 18종, 기대 분류번호 18건 일치 |
| 첫 업체가 연결되는 문진 선택지 | 9종 → 13종 |
| 연결되는 고유 일반 번호 | 12개 중 8개(해당 번호의 모든 재질을 지원한다는 뜻 아님) |
| 재질·형태 조합 | 52개 조회, 49개 후보 있음, 3개 업체 없음 |
| Azure 검토 | 49개 조합, 공정–업체 연결 95개, 반복 형태 포함 후보 검토 290건 |
| 공개 근거 확인 / 추가 근거 필요 | 38건 / 252건 |
| 최종 검토 키 누락·추가 / 호출 미완료 | 0 / 0 |
| 실제 반입 자동 승인 | 0, `dispatch_approved=false` 유지 |
| 서버 자동 검사 | SQLite 439개, 별도 PostgreSQL 시험 DB 439개 통과 |
| 웹 / route 자동 검사 | 웹 48개, route 520개 통과·72개 환경 의존 검사 제외 |

번호 일치는 연결 회귀검사이며 법률 전문가가 검수한 정답률이 아니다. 실제 Azure 검토는 저장된 공개 요약을 대조한다. 38건은 고유 업체 수가 아니며, `needs_evidence` 252건을 오류 없이 통과했다고 세지 않는다. [업체·형태별 보강 목록](registry-screen/intake-evidence-gaps-20261115.json)에 그대로 남겼다.

브라우저에서는 새로 연결한 세부 재질·형태 20개를 직접 선택했다. 재질 변경 시 형태 초기화, 모름 선택 시 보류, 비철 알루미늄 물량 등록·새로고침·실제 Azure 검토와 지도 표시를 확인했다. 500kg 합성 알루미늄 물량의 검토에는 합금·도금·수분 미확인과 추가 질문이 남았다. 이 결과를 실제 업체에 발송하지 않았다. 최종 브라우저 오류·경고 기록은 0건이었다.

**실패와 재시도도 있었다.** 문진 2건은 503 후 새 합성 건으로 재검사했다. Azure 첫 병렬 실행에서는 74개 후보 검토가 미완료였고, 해당 요청을 순차 재실행해 결과를 받았다. 이후 웹 재빌드 중 철스크랩 요청 1건의 연결이 종료되어 다시 실행했다. 최초 모델 미완료의 원인은 기존 로그만으로 확정하지 못한다. route에 원문·키·업체명 없이 실패 유형만 남기는 로그를 추가했다. 재시도로 결과를 받은 것을 운영 가용성 문제가 완전히 해결된 것으로 설명하지 않는다.

## 아직 보류하는 범위

- PE 베일(일반 수지·포장재), PS 베일: 3개 입력 조합에 수령 사업장 근거 부족. 공정·확인사항은 표시한다.
- 페놀수지·PU폼·양식용 부자·합성고무·금속용기: 실제 문진 5종은 아직 공정·사업장 연결이 없다.
- 구리 등 다른 비철, 혼합·미확인 재질: 이번 선택 목록에 없다.
- 업체별 허가 범위, 수분·이물·최소 물량, 당일 용량, 실제 수락: 미확인 상태를 유지한다.
- 회사 좌표가 있는 경우 최대 5곳을 **직선거리**로 표시한다. 도로 거리·운송비 산정은 이번 작업이 아니다.
- 이번 E2E 범위는 첫 업체 후보·AI 검토와 새 세부 재질의 물량 저장이다. 새 소재 전체의 A→B→C·QR 완료를 전부 실증했다는 뜻이 아니다. 기존 인계 회귀 검사는 유지했다.

## 적용 방법

server PR #47, web PR #46, route PR #61을 함께 적용한다. infra의 `.env`와 기존 DB를 유지한 채 서비스를 빌드하고 공정 참조를 다시 적재한다.

```bash
docker compose up -d --build
docker compose run --rm server-seed
```

서버 API에 optional `material_detail`을 추가했다. `next-step`, `intake-reviews`, `workflow/lots`에 같은 값을 전달한다. 기존 번호·인증·소유권·DB 테이블 계약은 유지한다. 상세: [명세](specs/material-detail-bridge.md).

재현은 [기존 실행 안내](classification-route-e2e-20261115.md#자동-검사와-재현)의 스크립트를 사용한다. `--materials ferrous_scrap nonferrous_scrap`으로 문진 범위를 좁힐 수 있다. 운영 환경에 실행하지 않는다. [최신 기계 판독 결과](material-detail-e2e-20261115.json), 로컬 원시 결과·화면은 작업 폴더 `output/verification/material-detail-20261115/`에 저장했다.

문서 영향 점검: API 추가 필드·실행 결과·보강 대기열·작업 목록을 갱신했다. DB 마이그레이션, 저장소 역할, AGENTS 및 에이전트 지침 변경은 없다.
