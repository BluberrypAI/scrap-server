# 공개 업체 검토 캐시 검증 (2026-11-19)

## 저장하는 것

공개 업체·공정·재질·투입 형태·출처 요약에 대한 검토만 PostgreSQL의 기존 `treatment_snapshots`에 저장합니다. 다른 처리 건에서도 같은 공개 입력과 모델/지침 버전이면 재사용합니다. 출처 내용·모델/지침이 바뀌거나 7일이 지나면 재검토합니다. 최대1024건이며 만료·오래된 결과를 정리합니다. 새로운 테이블이나 마이그레이션은 없습니다.

사진·중량·상태 설명·기업별 답변·이번 물량의 판단은 공용으로 저장하지 않습니다. 공개 근거가 확인된 업체만 사진·상태와 추가 대조합니다. 근거 부족·제한 결과도 재사용하지만 모델 미완료 결과는 공유하지 않습니다. 현재 물량의 캐시가 있어도 공개 근거 캐시가 만료되면 이전 물량 결과로 우회하지 않습니다.

캐시는 원문 수집을 대신하지 않습니다. TTL이 갱신됐다는 것은 저장된 공개 요약을 재검토했다는 뜻이며 사이트를 다시 수집했다는 뜻이 아닙니다. 업체의 현행 허가·당일 여력·이번 물량 수락은 별도 절차입니다.

## 실제 Azure 측정

이전 PP 시나리오와 같은 9개 업체 후보·공개 연구 사진을 사용하고, 매 실행마다 물량 캐시를 비우고 상태 설명을 다른 합성 물량으로 바꿨습니다. 기업·물량의 실제 거래가 아니라 엔진 성능을 확인하는 로컬 시험입니다.

| 경우 | 시간 | 공개 검토 AI | 물량 검토 AI | 사진 AI | 공용 캐시 재사용 |
| --- | --- | --- | --- | --- | --- |
| 공용 캐시를 처음 채우는 실행 | 85.729초 | 4회(여러 업체 묶음) | 1회 | 1회 | 0건 |
| 설명이 다른 새 물량 | 35.629초 | 0회 | 1회 | 1회 | 9건 |

두 실행 모두9개 후보를 확인해 공개 투입 근거가 확인된1곳을 반환했습니다. 이전 통합 검토의153초 사례보다 짧았지만, 모델 응답 시간은 변동하고 모든 물량이35초 이내라는 보장은 아닙니다. 실제 새 물량에는 사진·상태 검토 시간이 남습니다. 같은 처리 건의 정확히 같은 입력은 기존 건별 캐시도 재사용합니다.

## 검증 범위

- server: 전체642개 통과. 출처·모델 변경, 만료, 공용 캐시 재사용, 개인정보 제외, 모델 미완료/물량 판단 비공유, 용량 제한, 오래된 물량 캐시의 만료 우회 방지를 검사했습니다.
- route: 전체588개 통과,72개 환경 의존 건너뜀, 하위 검증24개 통과. 재사용된 finding도 출처·재질·형태 검사를 통과해야 하고 오래된 서명은409로 거절합니다. 현재 물량 모델이 실패하면 공개 사실만 남기고 물량 확인 완료로 만들지 않습니다.
- web:102개 통과, 프로덕션 Docker 빌드. Orb의 점과 궤도·글자를 SCRAP 보라색 계열로 변경하고 공개 근거 재사용/이번 물량 검토를 구분합니다.
- Ruff 검사·전체 포맷 검사 통과. 기존 Authlib/Starlette 사용 중단 경고와 웹 큰 번들 경고는 남습니다.

적용 순서는 route → server → web입니다. 기존 공개 검토 API 요청도 호환 유지합니다. 운영 배포는 기존 develop → main 릴리스 절차가 별도로 필요합니다.
