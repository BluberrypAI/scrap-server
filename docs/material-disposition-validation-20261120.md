## 발견한 버그와 수정

알루미늄 후보 검토 후 제이엠테크 계정을 연결했는데 후보 화면에는 수신 계정 없음이 계속 남아 인수 요청 버튼이 숨겨졌다. 원인은 AI 결과에 포함된 과거 recipient를 그대로 반환하던 것이다.

조회 응답에서 후보에 해당하는 현재 계정 연결·기업명을 DB로 다시 붙인다. AI 결과/근거/도로거리 캐시와 원본 검토 스냅샷은 바꾸지 않고, 조회로 revision을 올리거나 모델을 호출하지 않는다. 계정 연결 삭제·기업명 변경·운영 synthetic 차단도 즉시 반영한다. 인수 요청 API는 기존처럼 실제 DB 연결과 현재 권한을 다시 검증한다.

수정 후 **같은 알루미늄 검토를 재실행하지 않고** 새로고침만으로 요청 버튼이 나타났고, C 요청→수락→QR→완료까지 웹 통과했다. 회귀 검사에서 연결 전/후·기업명 변경·연결 삭제·운영 synthetic 차단 및 원본 캐시 무변경/AI 추가 호출0을 확인했다.

## 남은 데이터 공백

별도 PE 시험에서 펠릿→컴파운드의 유일한 BGF 화성 연결은 `site_role_hypothesis`여서 실제 Azure 검토에서 후보로 채택되지 않았다. 이것은 완료·보관 상태 오류가 아니라 사업장별 공정 근거 부족이다. 억지로 통과시키거나 산출물 형태를 바꾸지 않았다. 화면에서 같은 PE 펠릿을 완료로 전환해 끝낼 수 있음을 확인했고, **추가 PE 필름→파쇄품→펠릿** 시험을 만들어 C까지 검증했다. 따라서 검증한 대표8경로와 이 추가 경계 사례를 합쳐 총9건이다. PE 펠릿의 모든 후속 가공 업체가 확보됐다는 뜻은 아니다.
