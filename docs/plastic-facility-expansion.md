## 프로그램에서 달라진 것

1. **확정된 분류번호 + 수지 + 현재 형태**를 함께 확인합니다. PVC·발포수지·폐어망을 일반수지 번호로 대체하지 않습니다. 번호 체계 근거는 [별표 4](https://www.law.go.kr/LSW/flDownload.do?flSeq=170401309)이며, 이 모듈은 문진 결과를 새로 판정하지 않습니다.
2. 현재 단계의 모든 업체를 찾습니다. 미래 업체 조합이 늘어도 현재 후보가 탐색 한도 때문에 누락되지 않습니다. 지도 상위 5개 표시는 AI 검토 대상 전체와 별개입니다.
3. 공개 자료, 현재 상태·사진, 후보별 답변으로 AI가 검토합니다. 회사 제품 목록이나 이름만으로 반입 가능 판정을 내리지 않습니다.
4. 수신 회사가 수락하고 QR로 입고한 뒤 실제 산출물을 기록합니다. 그 상태로 C를 다시 조회·검토합니다. 일괄 처리 공장은 내부 세척·분쇄를 별도 운송으로 쪼개지 않습니다.

## 실제로 확인한 범위

- 자동 테스트 **232개 통과**, 별도 PostgreSQL 테스트 DB에서도 **232개 통과**.
- 신규 양성 조회 14개, 잘못된 수지·형태·번호 조합 10개 거부. 추가 44개 테스트에 포함됩니다.
- 가상 A/B 계정의 14개 단일 인계와 PP·PE·PET의 A→B→C 3개를 API로 실행: 후보 검토→수락→QR 입고→산출물→완료. 문진 응답·모델은 이 자동 테스트에서 대역을 사용했습니다. 실제 업체 수락이나 모든 소재의 실제 웹 문진 완주 시험은 아닙니다.
- 실제 로컬 서버/PostgreSQL에 47개 입력 조합을 조회하고 참조 결과와 일치 확인. 44개는 후보가 나오고 3개는 보류입니다. 그중 공개 사업장 공정 후보가 있는 조합은 37개, 역할 추정만 있는 조합은 7개입니다. **정확도 점수가 아닙니다.**
- 별도로 Azure 실호출로 공개 요약 기반 12개 후보를 검토했습니다. 5개는 문장 근거 확인, 7개는 추가 근거 필요, 통신 실패 0개. 인수 승인 0개. 세부 결과는 함께 올리는 scrap-route 문서를 참고합니다.
- 미래 사업장 연결 2,500개를 추가해도 현재 후보가 동일하고, 현재 후보 120개를 추가해도 모두 AI 전달 목록에 포함되는지 확인했습니다.

## 아직 비어 있는 부분

- **PE 베일(두 번호), PS 베일**은 다음 사업장 근거가 없어 `no_route`입니다. ABS 경질·스크랩, SAN 네 형태, PE 펠릿은 역할 추정 후보만 있습니다.
- 단일 PC·PLA·재질 미상 PA·미감용 EPS·혼합 수지는 일반 플라스틱으로 대신 연결하지 않습니다.
- 세부 수지 등급(HDPE/LDPE, HIPS/GPPS), 첨가제·난연제·충전재·수분 허용치와 현재 허가, 여유 용량, 가격, 개별 로트 인수는 업체 확인이 필요합니다. 제품 시험값을 반입 허용치로 쓰지 않습니다.
- 새 소재의 **처리 조회**와 **문진 엔진의 분류 지원**은 별개입니다. 팀 문진 메뉴를 임의로 늘리지 않았습니다. 확인된 handoff가 있어야 기업 인계로 진행할 수 있습니다.
- 주소·좌표가 없는 곳은 목록 후보로 볼 수 있지만 지도 거리 순위를 만들지 않습니다. 임의 좌표나 운송비는 넣지 않았습니다.

`backend/`에서 실행합니다. 참조만 갱신하면 기존 명부 9,604행과 인계 기록은 유지됩니다.

AI의 HTTP 출처 링크·추가 수지 검토 변경도 함께 적용하세요. 기존 데이터가 들어간 서버는 코드 pull만으로 DB가 바뀌지 않으므로 첫 명령이 필요합니다. [입력별 상세 후보 목록](plastic-coverage.json)으로 어떤 조합이 남아 있는지 확인할 수 있습니다.
