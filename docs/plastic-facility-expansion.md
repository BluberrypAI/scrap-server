## 프로그램에서 달라진 것

1. **확정된 분류번호 + 수지 + 현재 형태**를 함께 확인합니다. PVC·발포수지·폐어망을 일반수지 번호로 대체하지 않습니다. 번호 체계 근거는 [별표 4](https://www.law.go.kr/LSW/flDownload.do?flSeq=170401309)이며, 이 모듈은 문진 결과를 새로 판정하지 않습니다.
2. 현재 단계의 모든 업체를 찾습니다. 미래 업체 조합이 늘어도 현재 후보가 탐색 한도 때문에 누락되지 않습니다. 지도 상위 5개 표시는 AI 검토 대상 전체와 별개입니다.
3. 공개 자료, 현재 상태·사진, 후보별 답변으로 AI가 검토합니다. 회사 제품 목록이나 이름만으로 반입 가능 판정을 내리지 않습니다.
4. 수신 회사가 수락하고 QR로 입고한 뒤 실제 산출물을 기록합니다. 그 상태로 C를 다시 조회·검토합니다. 일괄 처리 공장은 내부 세척·분쇄를 별도 운송으로 쪼개지 않습니다.

## 실제로 확인한 범위

- 자동 테스트 **297개**, 별도 PostgreSQL 테스트 DB **297개** 통과. 기존 Authlib 의존성 경고 1개가 있습니다.
- 신규 10곳의 21개 소재·형태 조합이 다음 후보로 조회되고 전수 AI 전달 목록에 포함되는지 확인했습니다. PE관을 필름으로, 농업용 필름을 베일로, 생산 펠릿을 원료 스크랩으로 바꾸는 잘못된 연결도 검사했습니다.
- 가상 계정 API 시험: 기존 단일 인계 16개·두 단계 인계 3개에 **신규 PP·PE·PS A→B→C 3개**를 추가했습니다. 수락→QR 입고→실제 산출물→다음 후보 검토→완료를 확인했습니다. 문진·모델 응답은 이 자동 시험에서 대역이며, 실제 업체 인수나 웹 화면 시험은 아닙니다.
- 전체 검사에서 신규 PP 공정 2개의 R코드 검색 힌트 누락을 발견해 기존 PP 검색 기준과 맞췄습니다. 사용자의 확정 분류번호나 R코드를 새로 생성하지 않습니다.
- 실제 로컬 서버/PostgreSQL에 **48개 입력 조합**을 조회해 참조와 일치를 확인했습니다. 45개 후보, 3개 보류이며 정확도 점수가 아닙니다.
- 이번 Azure 실호출은 공개 요약·합성 입력 기반 **12개 후보**입니다. 근거 문장 확인 1개, 추가 근거 필요 11개, 통신 실패 0개, 인수 승인 0개. [이번 기록](registry-screen/live-validation-round3.json). 이전 11개 호출은 [과거 기록](registry-screen/live-validation.json)으로 보존하며 두 실행을 정확도 평가로 합산하지 않습니다.
- 공식 자료 대조기는 동명이인·건물번호·도로명/지번 불일치·빈 주소·원본이 아닌 HTML·CSV가 둘인 ZIP을 검사합니다. 이름·생산품이 맞아도 자동으로 반입을 승인하지 않습니다.

## 아직 비어 있는 부분

- **PE 베일(두 번호), PS 베일**은 다음 국내 사업장 근거가 없어 `no_route`입니다. [PRE 2026년 10월 자료](https://www.plasticsrecyclers.eu/wp-content/uploads/2026/10/Mapping-of-plastics-recycling-PRE-October-2026.pdf)의 베일 해체·결속재 제거·선별·분쇄 흐름으로 공정 근거는 보강했습니다. 유럽 일반 공정 자료를 국내 공장의 수행 증거로 쓰지는 않습니다. PE 등급/PS 종류, 베일 치수·중량·결속재·이물·해체 설비·반입 확인 자료를 요청합니다. B의 산출물이 베일인 경우에도 같은 보류가 적용됩니다.
- ABS 경질·스크랩, SAN 네 형태, PE 펠릿은 역할 추정 후보만 있습니다. 일반 PS 베일과 EPS 감용 인고트는 서로 대체하지 않습니다.
- 단일 PC·PLA·재질 미상 PA·미감용 EPS·혼합 수지는 일반 플라스틱으로 대신 연결하지 않습니다.
- 세부 수지 등급(HDPE/LDPE, HIPS/GPPS), 첨가제·난연제·충전재·수분 허용치와 현재 허가, 여유 용량, 가격, 개별 로트 인수는 업체 확인이 필요합니다. 제품 시험값을 반입 허용치로 쓰지 않습니다.
- 새 소재의 **처리 조회**와 **문진 엔진의 분류 지원**은 별개입니다. 팀 문진 메뉴를 임의로 늘리지 않았습니다. 확인된 handoff가 있어야 기업 인계로 진행할 수 있습니다.
- 주소·좌표가 없는 곳은 목록 후보로 볼 수 있지만 지도 거리 순위를 만들지 않습니다. 임의 좌표나 운송비는 넣지 않았습니다.

## 적용·재현

`backend/`에서 실행합니다. 참조만 갱신하면 기존 명부 9,604행과 인계 기록은 유지됩니다.

```bash
uv run python -m app.domains.treatment.import_catalog
uv run python ../scripts/plastic_coverage.py ../docs/plastic-coverage.json
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

AI의 HTTP 출처 링크·추가 수지 검토 변경도 함께 적용하세요. 기존 데이터가 들어간 서버는 코드 pull만으로 DB가 바뀌지 않으므로 첫 명령이 필요합니다. [입력별 상세 후보 목록](plastic-coverage.json)으로 어떤 조합이 남아 있는지 확인할 수 있습니다.

전수 선별 CSV를 다시 만드는 명령과 원본 해시는 [조사 대기열 설명](registry-screen/README.md)에 있습니다. 원본 전화번호·담당자 연락처, 기업 업로드 문서, 인증키는 이 배포 자료에 넣지 않습니다.
