# 업체 후보를 실제 문의로 이어가기

## 무엇이 달라졌나

이전에는 수신 계정이 없는 업체를 찾으면 인수 요청을 진행할 수 없었다. 이제 후보 카드의 **업체에 보낼 문의서**에서 현재 물량·공정·AI 확인사항·질문·근거를 묶어 미리 보고 복사하거나 텍스트로 저장할 수 있다. 사용자가 확인 후 업체에 전달한다. 자동 연락은 하지 않는다.

예: B가 처리한 철스크랩 950kg을 현대제철 인천공장에 문의하는 경우, B 사업장·현재 가공 철스크랩·54.0km 참고 도로거리·등급/성분/수분/인수용량 질문을 담는다. 처음 A에서 배출할 때의 분류번호는 최초 번호라고 표시하고 현재 산출물에 그대로 적용하지 않는다.

사업장 위치나 프로필을 바꾼 후 예전 검토로 인수 요청할 수 있던 누락도 보완했다. 문의서와 인수 요청 모두 현재 보유 기업·프로필·참조자료·반입자료·거리 서비스 버전을 확인한다. 변경됐으면 재검토를 요청한다.

## 검증

- 서버 **525개 통과**. 신규 7검사는 미가입 업체 문의 생성, 제3자·과거 보유자 접근 차단, 후보 바꿔치기, revision 충돌, 사업장 변경 후 문의/offer 차단, AI 실패/제한 유지, B 산출물 사용을 포함한다.
- 웹 기존 **66개 검사 통과**, 프로덕션 빌드 통과.
- 로컬 웹의 실제 B 계정에서 철 후보 문의서 열기·텍스트 다운로드 확인. 물량은 이전 도로거리 검사용 합성 상태이며 실제 기업에 연락하거나 운송하지 않았다.
- 문의 생성 후 기존 로트의 상태·revision·인계 목록이 바뀌지 않는지 검사했다.
- AI는 기존에 저장된 검토 결과를 사용한다. 이번 문의서 생성 때문에 새 Azure 호출은 하지 않는다.
- 이메일·계정 ID·QR 토큰·사진 파일/접근 URL을 자동 포함하지 않는다. 기업명·사업장 주소·사용자가 작성한 물량 설명은 포함되므로 내보내기 전 미리 보여준다.

## 파일과 데이터

DB 스키마 변경·데이터 재적재 없음. 서버는 인증된 요청에 텍스트를 반환하며 별도 파일을 저장하지 않는다. 응답은 private/no-store이다. 내려받은 파일의 공유·삭제는 사용자 관리다.

API: POST /api/v1/workflow/lots/{id}/inquiry-packet

입력: revision, capability_key. 출력: version, generated_at, filename, text.

server와 web을 함께 갱신해야 버튼이 동작한다. route/diagnosis 변경은 없다. 조건부 수락·최종 수락·QR 기준은 유지한다.

## 판매 가능한 제품으로 가기 위해 남은 검증

| 다음 일 | 완료됐다고 판단할 기준 |
| --- | --- |
| 실제 수신 업체 연결 | 업체 담당자가 자기 사업장을 확인하고 반입 조건을 직접 등록 |
| 실제 물량 파일럿 | 시험 계정이 아닌 배출자·처리자가 문의→수락→입고→산출물까지 진행 |
| 근거와 반입 조건 차이 해소 | AI의 미확인 사항에 대해 업체가 답하고 변경 이력이 남음 |
| 현장 효용 측정 | 기존 업체 탐색 시간과 서비스 사용 시간을 같은 업무로 비교, 문의 응답률·수락률 기록 |
| 운영 준비 | 실제 소셜 로그인, 백업 복구, 접근 권한 점검, 도로 서비스 운영 방식 검증 |

현재는 판매 검증이 끝난 제품이 아니다. 실제 업체의 확인과 현장 사용 결과는 공개 자료나 합성 테스트로 대신할 수 없다. 문의서 기능은 그 확인을 시작할 수 있게 하는 준비 단계다.

문서 영향 점검: spec·README·작업 기록 갱신. 에이전트 문서·DB 스키마·레포 역할 영향 없음.
