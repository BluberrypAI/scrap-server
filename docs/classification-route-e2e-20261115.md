## 검사한 흐름

`localhost:5178 웹 프록시 → server → 실제 diagnosis 질문·답변 → 결과 확정 → 서버가 handoff 재조회 → 현재 형태 선택 → PostgreSQL 공정·업체 조회 → route의 Azure 근거 검토`

- 합성 기업 계정과 시험용 물량을 사용했다. 분류번호나 handoff를 테스트 코드에서 대신 만들어 주지 않았다.
- 현재 범위인 플라스틱·고무 14개와 금속 4개 선택지를 전부 검사했다. 일반 조건에서 나오는 고유 번호는 12개다. **대한민국 전체 법정 분류번호 또는 문진 엔진 전체 분야를 모두 검사한 것은 아니다.**
- 18건은 HTTP로 실제 문진·확정을 진행하고, 같은 건을 실제 브라우저에서 열어 32개 형태를 모두 클릭했다. EPS 1건은 새 문진 시작부터 확정·업체 표시·Azure 검토까지 브라우저에서 추가로 진행했다.
- 이번 범위는 첫 업체 B의 후보 조회·근거 검토까지다. 모든 소재의 수신 기업 수락·QR·B→C·완료를 새로 검사한 결과는 아니다.

## 정상적으로 보류한 경우

- PE·PS 베일: 공정과 확인 조건은 화면에 남고, 연결된 수령 업체가 없어 인수 진행을 보류한다. 빈 화면은 아니다.
- 11개 수지·고무에 “유기용제 잔류” 조건을 넣은 별도 문진: 모두 `NEEDS_INTERPRETATION`과 `review_required`로 끝나며 일반 업체 후보를 제공하지 않았다. PP는 브라우저에서도 확인했다.
- 이 오염 시험을 지정폐기물 코드 11개가 확정된 시험으로 세지 않는다. 초기 시험의 재질별 지정 코드 기대값은 잘못된 전제였고, 실제 결과는 번호 미정·기관 확인이다. 원시 결과의 `code_matches=false`를 엔진 오분류 11건으로 해석하지 않는다.
- 확정 문진의 번호·근거는 형태 조회 후에도 그대로 보존됐다.

## 발견해서 수정한 화면 오류

MapLibre v6 지도 작업 파일이 Vite 빌드에 포함되지 않아 `Worker failed to load`가 발생했다. 지도 준비 표시와 마커가 보여도 로딩 오류가 남을 수 있었다. `scrap-web/src/pages/map/ResourceMapbox.jsx`에서 Vite의 `?worker&url`로 작업 파일을 빌드하고 `setWorkerUrl`에 연결했다. [공식 Vite 설치 안내](https://maplibre.org/maplibre-gl-js/docs/)를 따랐다.

로컬 Docker 웹을 재빌드하고 지원 9개 소재의 32개 형태를 다시 클릭했다. 재검사 기간 브라우저 오류·경고는 0건이었다. PET 화면에서 실제 배경 지도·사업장 마커를 확인했다.

사업장 좌표는 로그인 기업 프로필에서 읽는다. 이 합성 화성 기업의 PET병 후보는 6곳이지만 좌표가 있는 후보가 1곳이라 지도에는 1곳만 표시된다. 나머지는 목록과 AI 검토에 남는다. **Top 5를 채우기 위해 좌표를 추정하지 않으며, 현재 거리는 도로 거리가 아닌 직선거리다.**

## 먼저 채울 부분

1. **문진과 공정 입력 사이 세부 재질 연결:** 포장재 → 실제 PP/PE/PET 등, 폐어망 → 실제 PA6/PE 등, 기타 수지 → 실제 SAN/PA6/PA66/PC·ABS 등. 모름·혼합은 보류한다. 포장재를 PP, 어망을 PA6으로 일괄 치환하면 안 된다. 입력 보충은 확정 분류번호를 덮어쓰지 않고 물량·AI 검토·후속 인계까지 같은 값을 전달해야 한다.
2. **비철·용기 등 없는 공정 데이터:** 알루미늄 스크랩과 알루미늄 음료캔은 다르다. 기존 캔 업체를 비철 전체에 복사하지 않는다. 페놀·PU·고무·부자·금속용기는 공정과 업체의 적용 범위를 따로 확보한다.
3. **반입 형태 근거:** PE·PS 베일 업체를 보강하고, 이미 표시되는 업체에도 재질·투입 형태·사업장·제한 조건을 연결한다. 이번 AI의 151건 근거 부족을 건별 조사 목록으로 사용한다.
4. **좌표와 장애 원인:** 공식 주소에 대한 좌표 검수, 실제 도로 거리, AI 실패 사유의 민감정보 없는 기록·재시도 구분. 빈 후보·근거 부족·AI 장애를 혼동하지 않는다.

전국 명부 9,604행, 참조 사업장 50곳, 이번 첫 단계에서 도달한 사업장 46곳은 서로 다른 집계다. 명부의 모든 업체가 플라스틱 재활용 업체이거나 특정 형태의 수령 근거를 가진 것은 아니다. 동시에 현재 수작업 참조 연결만으로 추천하는 범위가 좁은 것도 사실이다. 명부의 번호 일치 업체를 추가 조사 후보로 넓히되, 검증된 공정·반입 근거와 구분해야 한다.

`scrap-server/backend`에서 실행한다. 로컬 가상 로그인·기업 등록과 전체 Docker 실행이 먼저 필요하다. 새 문진 건을 생성하므로 운영 데이터에 실행하지 않는다. Azure 검토는 실제 모델 호출이다.
