# 폐기물과 무관한 사진 예외 처리 — 2026-11-18

## 실제로 발견한 문제
로컬 통합 환경의 PE 시험 건(100kg, 합성 물량)에 저장소의 베리 캐릭터 PNG를 올려 실제 Azure로 검토했다. 모델은 캐릭터 그림이며 실제 폐기물 사진이 아니라고 판별했지만, 기존 화면은 후보 17개의 검토 완료와 업체 선택을 표시했다. 인식 결과를 진행 차단에 연결하지 않은 문제였다.

## 바꾼 동작
- 사진 관찰 중 하나라도 `visibility=not_waste`이면 모든 후보의 인수 요청을 차단한다. 웹에서도 후보 선택 대신 교체 안내를 표시한다.
- 확인 체크나 설명만 수정해서 이 차단을 해제할 수 없다. 분류번호는 변경하지 않는다.
- 현재 보유 기업이 현재 단계 사진을 교체한다. 원본 파일·기존 인계 이력은 유지하고 교체된 사진은 새 AI 검토와 새 인수 요청에서 제외한다.
- 교체 시 기존 검토를 초기화한다. 새 사진으로 검토해야 진행할 수 있다.
- `limited`는 무관 사진으로 단정하지 않는다. 기존 불확실성·반입 확인 절차를 유지한다.

## 검증 범위
- 실제 Azure 호출: 베리 캐릭터 1종. 기존에 저장된 17개 후보의 실호출 결과를 수정된 웹/서버에 적용하여 교체 안내·후보 숨김을 브라우저에서 확인했다.
- 자동 검사: 타 기업/이전 revision/누락 revision 교체 거절, 4장 한도에서 교체, 원본 조회 보존, 활성 사진만 AI·인수 요청에 전달, 무관 사진 인수 요청·확인·설명 수정 우회 차단, limited 구분.
- 웹 테스트 86개 통과. Docker 웹·서버 빌드와 기동 성공.
- 서버 전체 테스트 602개 통과(150.98초), Ruff 검사 통과. Authlib의 기존 의존성 사용 중단 예정 경고 1개.

## 한계와 배포
모든 잘못된 이미지를 완벽히 판별한다는 검증은 아니다. 실제 사진 위장·희미한 이미지·다른 물량 사진에 대한 모델 판정 정확도는 별도 평가가 필요하다. 사진만으로 PP/PE 재질과 성분·허가를 확정하지 않는다.
변경은 로컬 scrap-web과 scrap-server에만 적용했다. 운영 app.scrap-ai.org에는 아직 배포하지 않았다. 웹뿐 아니라 서버도 함께 배포해야 API 차단과 사진 교체가 적용된다.
